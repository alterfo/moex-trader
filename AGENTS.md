# Project rules

## Multi-session ownership (agreed 2026-09-16)

Two agent sessions share this repo. Zone boundaries:

1. **Ensemble + model zone:** ensemble lgbm+xgb+logreg @ buy/sell 0.60/0.40 and its Go inference, `internal/model/**`, `cmd/trainmodel`, `cmd/calibrate`, `cmd/exportdataset`, `internal/features/**`, `scripts/*.py`.
2. **Broker/sandbox zone:** `internal/broker/tinkoff/**`, `internal/ingestion/tinkoff/**`, `cmd/sandboxcheck/**`, `config.sandbox.yaml`, sandbox wiring in `cmd/trader` (`newBrokerRuntime`), Telegram alerting. Signal-source selection inside `cmd/trader` belongs to the ensemble/model zone.
3. The live/backtest signal source MUST implement both `orchestrator.SignalSource` (`Generate(ctx, feature) → BUY/SELL/HOLD`) and `backtest.SignalSource`, so it works in live sandbox and backtest without changes to executor/risk.
4. `cmd/trader` runs the preflight backtest gate before the live loop (`preflight.*` in the config): the current configuration is replayed over recent MOEX history and the trader refuses to start when **realized** P&L is below `preflight.min_net_pnl`, when closed trades are below `preflight.min_closed_trades`, or when history is unavailable for every ticker. The gate MUST use the same signal source as the live loop; do not bypass it or point it at a different source. The gate must also refuse to start (not silently "pass") when every decision in the replay errors out — a feature-count mismatch between `ensemble_model.json` and the current feature vector once made every decision fail, which looked like "0 trades, P&L 0, gate passed" instead of a hard failure.
5. Cross-session consultation goes through the user relaying messages (or agterm typing between panes) — headless `claude -p` returns 403 in this environment, there is no direct programmatic channel between the two agents.
6. **Failover zone:** `cmd/watchdog/**`, `cmd/witness/**`, `internal/failover/**`, `deploy/**`, `scripts/deploy-failover.sh`, `watchdog.yaml`/`watchdog.env` on the machines. Before touching election/witness logic run `go test ./internal/failover/ ./cmd/witness/ ./cmd/watchdog/`; the invariants below are load-bearing.
7. **Hard rule for all models — no concurrent code edits.** The two sessions share one working tree; only one may be writing code at a time. Before editing any tracked file, check `git status`/`git diff` and co-ordinate via the user that the other session isn't mid-change; concurrent edits tear the tree (the backtest realized/unrealized feature once landed uncommitted beside its own spec). Split work into read-only research vs. the single active writer, and commit promptly to shrink the dirty-window overlap.
8. **Metric-bearing changes are committed immediately (incident E4).** `docs/metrics.md` is the single source of truth for backtest/analysis numbers; any change that adds or edits a metric must land in the same commit. A session must only read metrics from `HEAD` or from an explicitly requested uncommitted file — an empty `git log -S` search does not prove absence when the working tree has uncommitted changes.

## Hard invariants

- All money is `decimal.Decimal`, never `float64` (GO_LIVE_CHECKLIST #1).
- Real-money live execution stays intentionally disabled — `cmd/trader` refuses to start against a non-sandbox account. Only paper mode and the T-Bank sandbox run today. Don't wire real order placement without an explicit go-ahead and a full go-live checklist pass.
- Automatic daily retraining with atomic replacement of the live model artifact (cron → walk-forward gate → hot-swap, no human review) was explicitly declined by the user on 2026-09-16: current baseline AUC (~0.50-0.52) is too close to noise for an ungated auto-swap to be safe with real money. Feature-drift/PSI diagnostics and a per-ticker circuit breaker are fine to build; the atomic auto-swap step needs new explicit sign-off before it's implemented.
- Two nodes (Mac primary, ai-box standby) share one sandbox account, so **only one may run `cmd/trader` at a time**. The right to trade is a lease from the VPS witness (`cmd/witness`); a node must stop its trader (fence) the moment its lease expires or is lost, and must never start the trader without holding a lease. Do not "fix" a fencing node by bypassing the witness or starting the trader by hand — a manual `./trader` on the non-lease-holding machine is exactly the double-trading failure the witness exists to prevent.
- Never pick the authoritative `trader-sandbox.db` by file mtime: a freshly created empty DB has a newer mtime than the working one and will clobber it (this happened on 2026-09-16, wiping the sandbox audit history; the account was flat, so only statistics were lost). The source is the node whose trader started last (`trader.last_start_at` in the heartbeat); a DB accepted from the peer is marked synced and the local node reclaims ownership when its own trader starts. Downloads are validated as SQLite before replacing the local file.
- A node that fails to start its trader `trader.max_failures` times releases the lease and stays in `error` (not `standby`) while its `post_failure_cooldown` lasts — otherwise the peer sees a healthy-looking standby and never takes over. The cooldown (30 min) is deliberate anti-ping-pong for a globally broken model.
- The watchdog on the Mac runs `./trader` from the repo root; `scripts/deploy-failover.sh mac` rebuilds it. The ai-box runs its own linux/amd64 build with `SSL_CERT_FILE=certs/ca-bundle.pem` (system CAs + Russian Trusted Root/Sub CA, needed because T-Bank uses the Russian CA chain and Ubuntu does not ship it).

The deployed `ensemble_model.json` trains on only the 18 price/flow columns; the remaining 10 names are zero-coefficient placeholders that preserve live feature-order parity.

Without that flag, or for dates/tickers missing from the archive, all three groups still fall back to 0 — a feature-importance run on a dataset built without `-news-history` will still show them as dead weight for that reason alone.
- `SBMM` (ETF "Первая – Фонд Сберегательный") is NOT tradable via the T-Invest API (`apiTradeAvailableFlag=false`) — dropped from the ticker list and replaced with `POSI`. Don't reintroduce it as an order target.

## XGBoost/LGBM → Go inference (solved — don't re-derive)

- Export with `booster.save_model("model.json")` (full native format). Never `dump_model()` (lossy, different node schema, no `base_score`) or `save_raw()` without `raw_format="json"` (defaults to a UBJSON binary in modern xgboost — feeding that to a JSON parser is what caused a parse hang during development).
- `learner.learner_model_param.base_score` in that JSON is a **string wrapped in brackets**, e.g. `"[4.7E-1]"` — strip the brackets before parsing as float.
- With `boost_from_average` (xgboost's default), `base_score` is stored in **probability space** (the label mean), not margin space — transform via `base_logit = log(bs/(1-bs))` before summing with tree outputs. This was independently re-derived and confirmed twice (both agent sessions, separately) against `predict_proba` — trust it without re-deriving again unless a fresh accuracy check disagrees.
- Leaf value = `split_conditions[node]` at a **leaf** node (`left_children[node] == -1`). `base_weights[node]` only equals it at leaves; at internal nodes it is neither the split threshold nor a usable leaf value.
- XGBoost's internal split comparisons are float32; LGBM's are float64. Quantize XGB tree inputs to float32 before comparing against split thresholds, or you'll see ~0.01-level mismatches at certain boundaries. Verified end-to-end accuracy vs Python `predict_proba`: 6.4e-8 max abs error on the full validation set.
- Final probability = `sigmoid(base_logit + Σ leaf values across all trees)` for `binary:logistic`.
- LGBM tree JSON recursive builder gotcha: append a `-1` placeholder for a child index **before** recursing, then overwrite it (`lc[i] = walk(...)`). Appending the recursive call's result directly (`lc.append(walk(...))`) executes children out of order and corrupts the flat array indices.

## GDELT — tried and abandoned, don't reintroduce

- Fully removed (`cmd/gdeltnews`, `internal/ingestion/gdelt`, related flags in `trainmodel`/`calibrate`) after repeated instability: geo-blocked without a SOCKS proxy, a strict 1-request/5s rate limit, and still sporadic 429s needing 55-90s backoff even through the proxy. Historical news now goes through `internal/ingestion/news` (RSS) instead. Don't re-add a GDELT dependency without solving the rate-limit problem first.
- `Kasymkhan/RussianFinancialNews` (HuggingFace; mirrored on Kaggle as `kkhubiev/russian-financial-news`) is a candidate historical news dataset, but it only covers 2009-06-19..2024-12-16 — it does not overlap the current training window (2024-09..present) and is not a substitute for live news history.

## Paid news API/channel — investigated and rejected (2026-09-28)

- Triggered by "should we pay for a news feed to fix RSS instability/coverage." Cross-verified by two independent agents (this session + an `opencode` session in the neighboring agterm pane) researching in parallel, plus live probes against every candidate. Verdict: **nothing to pay for.**
- **Root cause of the instability was a code bug, not a rate-limit/coverage problem** — see the `User-Agent` bullet above. Fixing it is free.
- **The trading loop caps how much news latency can matter anyway.** `cmd/trader` runs its whole decision cycle on `poll_interval: 5m` (`config.yaml`), and the news-veto gate (`newsGateSignalSource.Generate`) only gets evaluated once per cycle — sub-minute news delivery buys nothing until that cadence itself is shortened. The bigger latency ceiling is free MOEX ISS quotes lagging **~15 min** for stocks (`docs/plans/20260927-moex-pulse.md`) — two orders of magnitude bigger than any RSS-vs-paid-API gap. Don't relitigate "pay for lower news latency" without first shortening `poll_interval` and moving off delayed quotes.
- **Licensed RU wires (Интерфакс СКАН/IFX, AK&M, ТАСС Б2Б, `commerce.1prime.ru`) don't publish self-serve pricing and gate onboarding behind a signed договор with a legal entity + a расчётный счёт** — not accessible to an individual regardless of budget. AK&M's own order form has no field for a physical person.
- **T-Invest API has no news endpoint** — confirmed against the live gRPC gateway (`NewsService/GetNews` → 404 on every host/token tried) and by grepping the full Finam Trade API REST reference (39 endpoints, zero `news`/`feed` hits). Neither broker integration already in this repo can supply news for free.
- **Foreign news APIs don't reliably cover RU/MOEX names.** Marketaux indexes 14 of our 17 tickers as entities (`TICKER.ME`) but its live `countries=ru` query returned `found: 0` articles; Event Registry's RU coverage is unverified (endpoints 401 without payment). NewsAgent Data ($29+/mo, the only vendor with a published self-serve price) turned out to be an aggregator of the same public RSS/Telegram sources we already poll, with no per-ticker filter field, and its free tier returned zero verifiable RU articles.
- **Free sources added instead:** `iss.moex.com/iss/sitenews` (exchange operational notices, no auth, `SourceTypeMOEXSiteNews` in `internal/ingestion/news`), `cbr.ru/rss/RssPress` + `/RssNews` (Bank of Russia — the only source covering the regulator, whose rate decisions drive SBER/VTBR/T/POSI directly), and per-ticker `news.google.com/rss/search` feeds (`GoogleNewsSources`/`AllSources` in `internal/ingestion/news/sources.go`, query = primary alias from `DefaultAliases()` + "акции"/"цена"/"курс") are all wired into `news.AllSources(cfg.Tickers)`, used by both `cmd/trader` and `cmd/newsfetch`. Google already dedupes the same wire-copy story arriving from 4-5 of the hardcoded RSS feeds — it's additive coverage, not a dedup mechanism for the existing sources. `disclosure.1prime.ru` (ЦБ-accredited issuer material-facts server, free to read, keyed by ИНН/ОГРН not ticker) was verified live but **not yet implemented** — no RSS/API, needs a bespoke scraper plus an ИНН→ticker map (buildable free from `iss.moex.com/iss/securities.json`); pick this up as a follow-up task, not a quick fix.
- **ToS decision TAKEN by the user on 2026-09-29 (supersedes "flag, not yet acted on"):** Telegram's Content Licensing terms prohibit using platform data to train/fine-tune ML models, and Google News RSS's feed copyright notice restricts use to "rendering results within a personal feed reader for personal, non-commercial use". Presented both explicitly (Telegram 2 channels MarketTwits/Банкста, plus 17 per-ticker Google News feeds added 2026-09-29) as a gate with an RSS+MOEX+ЦБ-only alternative; **the user chose to include Telegram and Google News in the training set, knowingly accepting the exposure.** The archive records `source` and `trust_weight` per record (`cmd/newsfetch` `record` struct), so a source-filtered rebuild remains possible later if the decision is reversed. Everything below about the sentiment classifier's numbers is therefore measured on a set containing ToS-restricted sources — do not present those numbers as if the sources were clean, and do not silently continue the backfill without re-confirming this decision.
- The same decision applies to the *price* model's `-news-history` backfill path, not only to `cmd/trainnewsmodel`.
- **Sentiment classifier is DEAD and retraining cannot fix it (2026-09-29, second larger attempt).** The deployed `news_classifier.json` scores 92% of headlines inside ±0.1 (range [−0.247, +0.266] over 800 unique archive headlines, only 7.8% exceed |0.1|) — `news_sentiment` contributes ~nothing to the live feature vector, and its val acc 0.529 is below the 0.552 majority baseline. Rebuilding the archive from scratch (9596 articles: RSS/Google/ЦБ/MOEX `-since-days 30` + Telegram `-retro-from 2026-04-01`) and retraining produced **four** variants, all below baseline accuracy (val AUC 0.493–0.540, accuracy 0.469–0.538 vs baseline 0.511–0.580) with a 0.31–0.46 train→val AUC gap. The freshly trained models are *alive* (~64% of scores exceed |0.1|) while the deployed one is dead — so deploying any variant would replace a harmless near-zero feature with an actively wrong one. Kept the 2026-09-16 artifact. Full table and the behavioural scoring run are in `docs/metrics.md` ("News classifier rebuild from a fresh 9596-article backfill").
- **The archive cannot be rebuilt to the 2026-09-16 depth (17x sample loss).** 9596 articles yield only 2855 train samples: `BuildNewsLabels` drops tickers whose `source.History` fails (`internal/model/newsclassifier.go:246`) and truncates the tail where `exitIdx >= len(candles)`. The 2026-09-16 classifier had 48294 train samples vs 2855 today, because Telegram retro reaches only 2 channels and RSS/Google expose no history API. Don't re-attempt a one-off backfill retrain — it is the documented data-scarcity bottleneck, not a tuning problem. Retry only after months of live `cmd/newsfetch` appends build a direction-label-balanced corpus.
- `cmd/trainnewsmodel` does **not** filter by configured tickers — it trains on every ticker in the archive. A fresh backfill is dominated by non-config names (VKCO alone was 41.5% of 9596 records, plus 8.5% FX tickers that the model must not trade at all), which is why filtering to the 17 config tickers *hurt* (val AUC 0.493, 759 train samples). Pre-filter the archive to `config.tickers` before training, and keep FX (`GLDRUB_TOM`/`SLVRUB_TOM`/`CNYRUB_TOM`) out of it entirely.
- Google News RSS needs `?hl=ru&gl=RU&ceid=RU:RU` and returns a redirect (`302`) before the real feed — Go's `http.Client` follows this automatically, no special handling needed, but don't strip query params when building the URL or the redirect target loses `ceid` case-normalization.

## Strategy research: absolute label + target-position sizing (2026-09-16, H1+H2)

- **Label vs execution mismatch (H1)**: training labels are excess-to-IMOEX while execution takes absolute long/short positions. `BuildSamples`/`cmd/exportdataset`/`cmd/trainmodel` support `-label-mode absolute`; on a 6-quarter walk-forward (18 equities, 1M deposit, 0.05% commission) the absolute label turned the OOS result from ~0 (excess: +235₽ total, 2/6 quarters positive) into consistently positive P&L. FX tickers (`GLDRUB_TOM`, `SLVRUB_TOM`, `CNYRUB_TOM`) must not be traded: the IMOEX-relative label is meaningless for them and every model that traded them lost 1.2-1.5k₽ on a single gold short.
- **Best found recipe** (walk-forward, 6 quarters, kill-switch on): absolute **10-day** label, deadband 0.5%, thresholds 0.60/0.40, flat **15000₽ notional per position** via `-target-notional` + target-position execution. Result: realized +110742₽ over 18 months (5/6 quarters positive, worst quarter -6238₽), max DD 2.91%, kill switch never tripped (~7%/yr at ~27% max exposure).
- **Rejected after walk-forward**: 1d/3d/5d horizons (weaker than 10d); thresholds 0.65/0.35 (worse than 0.60/0.40); confidence-scaled sizing `min(1, |p-0.5|/0.2)` (churns 300+ trades, loses vs flat notional); notional 20000₽ and the 42-ticker universe (DD 3.8-3.9% breaches the 3% kill-switch limit).
- **Risk gate limits bind sizing**: 0.5% daily loss / 3% drawdown of deposit cap P&L at larger notionals — P&L scales sub-linearly; pick size so max DD stays under 3%.
- **Live wiring done (2026-09-16)**: `risk.target_notional` config field (+ env override) drives `EnsembleSignalSource.TargetNotional` in `cmd/trader`; real Tinkoff exchange lot size is now resolved and cached per ticker (`brokertinkoff.Sandbox.ResolveLotSize`, backed by `ShareBy`) and injected into `FeatureContext.LotSize` via a `lotSizeSignalSource` decorator before the model sees the signal. This mattered: the walk-forward validation above never modeled real lot size (backtest always saw `LotSize=0`, i.e. implicitly lot=1/share-based sizing); of the 18 tradable equities, GAZP/GMKN/MTSS/RUAL actually trade in lots of 10 (checked live via Tinkoff sandbox `ShareBy`, rest are lot=1) — without this fix, live orders on those 4 tickers would have been sized ~10x too large. The quantization this introduces vs. the walk-forward's continuous sizing is minor (~7-13% step at 15000₽ notional) and not expected to change the sign/order of magnitude of the result, but it hasn't been re-validated in a lot-aware backtest.
- **Feature-subset rule (2026-09-17)**: the 8 event features are structurally zero without a news/event backfill, and with `colsample_bytree`/`feature_fraction` 0.8 they *dilute* the sampled columns and degrade the walk-forward result (18 trained columns + 0.8 = +110741₽; the same recipe over 26 columns = +80716₽; colsample 1.0 = +87823₽). The deployed `ensemble_model.json` therefore trains on the 18 price/flow features and exports `feature_order` over the full 28-name order (`ENSEMBLE_FEATURE_ORDER` in `scripts/export_ensemble.py`, logistic arrays expanded by name), so live inference still passes the feature-order check. Revisit once event/topic features carry real data.
- **Time-exit rejected for the daily strategy (2026-09-17)**: `-max-hold-bars 10` (exit at the label horizon) scored +52498₽ vs +87823₽ for hold-until-flip on the same 6 windows (worse in 4/6, q4 -17388₽ vs -7671₽). The engine supports both (`MaxHoldBars` and flat signals), but daily trading should hold until the signal flips.
- **Intraday 10-min has no edge (2026-09-17)**: 10-min ISS pipeline (62k train bars, 6-bar horizon) gave val AUC 0.5173 and ~-12.8k₽ val P&L with the kill switch tripping — the same ~0.52 AUC ceiling as daily. More data volume alone did not create edge, so "data volume is the bottleneck" is not confirmed by this test. **Dropped by user decision (2026-09-17): no intraday scalping.**
- **Retrained artifact (2026-09-17)**: `ensemble_model.json` is now the absolute-10d recipe (18 features, colsample 0.8, 28-name order with zero-weight placeholders); preflight window +79453₽, DD 0.84%, kill switch off. `config.sandbox.yaml` is updated to match: `ensemble_path`, `risk.target_notional: "15000"`, `risk.max_lots: 1000` all active (commit 722353e); lot size comes from `brokertinkoff.Sandbox.ResolveLotSize` injected as `FeatureContext.LotSize`.
- **Invariant rule — judge strategies by realized, not MTM (2026-09-17)**: a backtest's headline Net P&L must always be split into realized (closed trades, gross − commission) and unrealized (open positions at the cutoff date); MTM is shown separately but never drives a go/no-go. This is the second time the two were conflated — for cross-sectional csvprob: `xsec_full.md` Net +8061 is MTM with realized only +621.80₽ over 2 years (gross +820.22 − commission 198.42), and `xsec_0.8_3000.md` headline +2020 is entirely open-position MTM while realized is −5068₽ (gross −4977.37). A spread proxy (half-spread per side, e.g. `(High−Low)/Close/4`) must be included before trusting any backtest on mid/low-liquidity names — commission×4 is not a substitute for 0.5-2% spreads.
- **Cross-sectional ranking closed (2026-09-17, user decision)**: xsec/csvprob is NOT an upgrade over the deployed abs-10d recipe — realized ≈ 0 (minus on liquid large caps), top "wins" are a handful of multi-month directional bets in mid names (CHMF SELL +1906₽ held 9 months, BANEP/ENPG/ALRS) that backtest's no-spread model can't price, and DD 4.26% breaches the 3% kill-switch limit. abs-10d stays the live signal (realized +110741₽/18mo on 18 liquid names, DD ≤2.91%). Do not reopen this direction without a realized-vs-MTM split and a spread proxy in the validation.
- **Backtest spread+slippage added (2026-09-17)**: `backtest.Config.SpreadPct`/`SlippagePct` (CLI: `-spread-pct`/`-slippage-pct`, default 0 = old behavior) widen every fill against the trader — BUY up, SELL down — applied in `Engine.fillPrice`, covering opens/adds/reduces/flips and `-max-hold-bars` forced exits. Not wired into `cmd/trainmodel`'s holdout validation yet. On the deployed abs-10d ensemble (18 liquid names, 15000₽/position, 18mo): no-cost +43891₽ → realistic (0.05%+0.05%) +43082₽ (−1.8%) → harsh (0.1%+0.1%) +42270₽ (−3.7%); strategy stays profitable but headline P&L without costs is optimistic by a few percent.
- **Live order-execution safeguards added (2026-09-17)**: Tinkoff sandbox was placing bare `MARKET` orders (no price bound at all — the exact "stop-market sweeps the book" risk). - **`max_net_exposure` means GROSS, not signed net (2026-10-01)**: the cap
  bounds `Σ_ticker |signed position notional|`. The old signed-net basis was
  blind to gross risk — long 500k SBER + short 500k OZON net to **zero** and
  passed a 60k cap carrying 1M of risk — and made *which* names filled depend
  on how much opposing exposure was booked first. Flag/config name
  (`-max-net-exposure`, `MaxNetExposure`) unchanged on purpose.
  Three invariants when touching this cap:
  (1) **Project per ticker, never book-wide addition.** The order replaces only
  its own ticker's leg; the bound is `|other names| + |this name after|`.
  Adding `|delta|` to total gross makes the cap reject *risk-reducing* orders —
  an intermediate implementation passed cap 0 and silently blocked every
  flatten-to-flat order (all-short grid: 2-6 closed trades → **0**, drawdown
  unchanged, result left as open-position MTM).
  (2) **`Signal.TargetLots` is NOT the exposure delta.** In the target-position
  path it is the absolute target that `recordFill` reconciles to; reading it as
  a delta double-counts the held position (a real pre-existing bug, fixed here).
  `risk.Request.ExposureDeltaLots` carries the signed delta; nil means
  "TargetLots is the order size" (live `EnsembleSignalSource`, incremental).
  (3) **Re-run the all-short grid** (`docs/metrics.md` "signed net → gross")
  after any cap change — net ≡ gross there, so every row must stay bit-identical;
  a changed row means the projection is wrong, not that the market moved.
  Live keeps `max_net_exposure: 0`, so this commit changed no live behavior.

## Strategy validation tooling (2026-09-17)

- Purged walk-forward is the standard validation: `-embargo-bars 10` in `cmd/walkforward`, `cmd/backtest -wf-dir` and `cmd/trainmodel` (mirrored in `scripts/export_ensemble.py`) drops every training row whose label exit reaches the test window, so the 10-day label no longer overlaps train and validation. The purged run is the deployment-gate control.
- Live-vs-backtest parity: features are built from closed bars and `return_pct` comes from candle closes (`closedBarReturnPct`), not the intraday `LastPrice`; the shadow reconciler (`--shadow-digest`) writes a digest and flags an unclosed trailing bar or a replayed-signal mismatch.

## Live/sandbox operational notes

- Kill switch must only cancel orders for instruments the bot actually trades (its own ticker set) — it must never touch a human's manual orders on the same account. (Regression test: `TestCancelOpenOrdersLeavesForeignOrdersAlone`, added after it was found cancelling unrelated manual orders.)
- The bot only tracks positions from its own fills — it has no visibility into shares a human holds manually on the same account. A SELL signal on a ticker the human also holds manually will be interpreted as opening a short, not "selling the human's shares." This matters before ever wiring live execution onto an account that already has manual positions.
- Telegram: `api.telegram.org` is blocked directly from this environment — route through `telegram.proxy: "socks5://127.0.0.1:3333"`.
- Nightly evening digest (`telegram.daily_summary_enabled` + `daily_summary_time`, default 19:05 MSK): after the close the trader sends a brief Telegram summary — bot day P&L (realized net of commission + MTM change of open positions, `internal/dailysummary`, average-cost accounting mirrors `risk.TickerBreaker`), number of fills, IMOEX daily % and the share of configured tickers that closed green — market context for the user's manual long positions. Runs only inside the lease-holding trader (no duplicate from the standby); non-trading days (weekends/holidays) are skipped via the IMOEX candle date, so it needs only config, not a cron entry. Deployed `config.sandbox.yaml` enables it.
- Finmarket's RSS feed is Windows-1251, not UTF-8 (`internal/ingestion/news/news.go` decodes via `charset.NewReaderLabel`) — don't assume every feed is UTF-8.
- **RSS 429s were a missing `User-Agent`, not real rate limiting (2026-09-28).** `Fetcher.Fetch` sent Go's default `Go-http-client/1.1` UA; live-verified vedomosti.ru returns 429 on 6/6 requests with that UA and 200 on 6/6 with a browser UA. Fixed by setting `newsUserAgent = "Mozilla/5.0 (compatible; moex-trader/1.0)"` (already used by `FetchTelegram`, now shared) on every RSS/JSON request in `internal/ingestion/news/news.go`. Don't add a proxy or paid feed to chase this class of failure again — check the UA first.
- AlgoPack enrichment silently disables itself (one log line) when `MOEX_TRADER_ALGOPACK_TOKEN` is unset, instead of logging a 401 per ticker per cycle.
- Orders are guarded by `TradingStatus` — the bot checks whether the MOEX session is open before submitting, instead of hitting error `30079` (`Instrument is not available for trading`) or burning API rate limit outside trading hours.
- `risk.Gate.ApproveReason` (2026-09-19) returns a `risk.Decision{Approved, Reason}` and the orchestrator now persists the reject reason in the `risk_gate` audit payload (e.g. `{"approved":false,"reason":"fat_finger"}`). `Approve` remains as a delegating wrapper so backtest and callers needing only the bool stay unchanged.
