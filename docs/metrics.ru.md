# Метрики

Эмпирические результаты исследовательской программы MOEX Trader, оформленные как единая работа в научном стиле: постановка, метод, результаты по темам, синтез. Это единственный источник истины для всех чисел бэктестов и анализа в репозитории (правило 8 в `AGENTS.md`: изменение, добавляющее или правящее число, попадает в тот же коммит, что и код или план, к которому оно относится). Состояние на 2026-10-19. Предыдущая, хронологическая версия (около 2500 строк, по разделу на задачу) сохранена в истории git в коммите `82a124b` (`git show 82a124b:docs/metrics.md`); Приложение A сопоставляет её названия разделов с разделами ниже, поэтому старые ссылки остаются разрешимыми.

## Аннотация

1. **У развёрнутого ансамбля на ценовых признаках и признаках потока нет доказуемой предсказательной силы.** Валидационный AUC лежит в диапазоне 0.46-0.55 в зависимости от рецепта и окна оценки; шум самой процедуры оценки равен 0.016 AUC на 95-м процентиле (раздел 3.6). Хвостовые решения (p >= 0.60 или p <= 0.40) попадают в 42.4% при базовой частоте 47.7% (bootstrap p = 0.9123, раздел 3.1).
2. **Его реализованный P&L в основном состоит из рыночной беты.** На 2025-04..2026-09 книга заработала +194293 RUB реализованными, из которых компонента IMOEX составляет около двух третей (сдвиг в шорт на падающем индексе). Нейтрализация беты реальным фьючерсом на IMOEX убирает альфу (t = -0.49 ... +0.39, раздел 5.4); метки «избыточная доходность к IMOEX» вдвое снижают нагрузку на бету, но оставляют остаточную альфу с t около 2.0, не дотягивающую до зарегистрированной планки (раздел 5.5).
3. **Ни один вариант рецепта не проходит предварительно зарегистрированный гейт развёртывания** (метки с учётом дивидендов, широкая обучающая выборка, калибровка и отдельные члены ансамбля, масштабирование по волатильности, секторные лимиты, метки избыточной доходности, более глубокая история, метки в единицах волатильности, ранговые признаки, TimesFM, открытый интерес, ширина широкой панели; разделы 4 и 6). Ближайший, логистический отдельный член, не проходит критерий просадки.
4. **Новости и событийная информация дают мало.** AUC классификатора заголовков достигает 0.52 только на 19-24 тысячах образцов; за вычетом издержек спред между верхним и нижним квинтилем равен +0.263% на транш с доверительным интервалом, охватывающим ноль (раздел 7). Направление, которое zero-shot LLM даёт по русским заголовкам, не лучше случайного (AUC 0.511-0.526). Событийные исследования санкций, переговоров, пересечений уровней и всплесков новостей не находят торгуемого эффекта.
5. **Календарных эффектов, циклов и внутридневных закономерностей нет после 1990 года / после издержек** (раздел 8.11). Овернайт-премия (+0.07-0.10% в день) реальна, но меньше 0.30%, нужных для торговли ею.
6. **Единственный положительный результат — кросс-секционный.** Ridge-модель на point-in-time панели всей доски TQBR (ежемесячная ребалансировка, 2019-2026) даёт длинную книгу минус вселенную +1.07% за период (Newey-West t = 3.35, Sharpe 1.11), проходя зарегистрированное правило; её long-short форма не дотягивает по t (2.54) и требует стоимости займа шорта ниже примерно 5% годовых, которую никогда не измеряли (раздел 8.6). Как кандидат для живого гейта она проходит скользящий гейт в 59% окон, а не в зарегистрированных 70% (раздел 8.8).
7. **Дрейф SELL в сентябре-октябре вызвал дефект живого контура, а не модель**: до 2026-10-09 работающий трейдер подавал немаскированные `news_count` и `news_sentiment` в модель, обученную на нулях (раздел 9.1).
8. **Безрисковая планка высока**: ключевая ставка 14% приносит +12347 RUB в месяц на 1M RUB; каждое записанное здесь окно стратегии заработало меньше (раздел 8.12).

## 0. Соглашения

### 0.1 Величины

- **Реализованный P&L** — валовый P&L закрытых сделок минус комиссия (и минус заём, где указано); **MTM** — переоценка открытых позиций по рынку. Решения go/no-go определяет только реализованный P&L; MTM приводится отдельно.
- **Издержки** («0.0005 x 3»): комиссия 0.05%, спред 0.05% и проскальзывание 0.05% на исполнение, если не указано иное. **Стресс займа**: 0.00005 в день (0.005% в день, 1.8% годовых) на шортовый номинал. Депозит 1M RUB, целевой номинал 15000 RUB на позицию, пороги BUY p >= 0.60 и SELL p <= 0.40, удержание до смены сигнала, kill switch по просадке включён.
- **AUC** — площадь под ROC-кривой предсказанной вероятности относительно реализованной метки направления; 0.5 — случайность. Разница между единичными конфигурациями ниже 0.005 AUC считается шумом (исходная полоса); измеренный шум процедуры оценки больше (раздел 3.6).
- **Sharpe** в `internal/backtest` аннуализируется по дневным доходностям капитала с выборочным стандартным отклонением, умноженным на sqrt(252); `internal/strategyvalidation.SharpeRatio` — неаннуализированный выборочный Sharpe за период, намеренно совпадающий по гранулярности с рядом, который он дефлирует (PSR/DSR). Эти два значения несопоставимы. Sortino использует только отрицательные доходности; CAGR = (final/initial)^(365.25/days) - 1; Calmar = CAGR / |максимальная просадка|. Прогоны с менее чем 30 закрытыми сделками помечаются предупреждением.
- **Интервалы** — доверительные интервалы bootstrap по блокам дат или по ISO-неделям (seed 42 или указанный; 2000-5000 повторов); поправки на множественные проверки (Bonferroni, Holm) указываются для каждого теста. `t` — Newey-West или кластеризованный по датам, как указано.

### 0.2 Окна

Шесть purged walk-forward окон («окна Task 5»): q1 2025-03-05..06-05, q2 2025-06-06..09-05, q3 2025-09-06..12-03, q4 2025-12-04..2026-03-04, w2 2026-03-05..06-06 и w1 2026-06-07..09-16; окно h — 2026-09-17..10-17 (hold-out), окно G — 2026-07-20..2026-10-18 (90-дневное окно preflight гейта).

### 0.3 Метод фиксации результатов

Каждый эксперимент следует предварительно зарегистрированному плану (`docs/plans/`, закоммиченному до первого запуска) с числовыми критериями приёмки. Вердикт выносится только по этим критериям; всё, что вычислено после просмотра результатов, помечается как описательное и не может обосновывать решение. Сравнения, зависящие от рецепта со случайностью обучения, делаются с свежим контролем того же прогона, а не со старым числом из реестра (дрейф стека: версии библиотек менялись между 2026-10-04 и 2026-10-18; движок на HEAD воспроизводит архивный артефакт примерно на 93%).

### 0.4 Происхождение чисел

Результаты с датой до 2026-09-17 включительно (строки реестра, разделы 3.1-3.4, 5.1-5.2) получены до исправлений по ревью от этой даты: признаки живого контура и бэктеста теперь используют полный 300-барный lookback (434 календарных дня), чтобы индикаторы EMA/SMMA сходились как в живом контуре, `realized_volatility` ограничена этим окном, живые признаки используют только закрытые дневные бары, а `backtest.LoadNewsOverrides` взвешивает новости по `trust_weight`. Эти результаты сохранены для прослеживаемости и должны быть пересчитаны перед повторным использованием в качестве доказательства; purged-базовая линия от 2026-10-04 (раздел 3.5) и всё после неё используют исправленный конвейер.

### 0.5 Правило процесса (инцидент E4)

Изменения, несущие метрики, коммитятся сразу. Сессия читает метрики из `HEAD` или из явно запрошенного незакоммиченного файла; пустой результат поиска `git log -S` не доказывает отсутствие, пока в рабочем дереве есть незакоммиченные изменения.

### 0.6 Структурная устойчивость и граничные оптимумы

Вывод по одной спецификации (один seed, одно разбиение окон, один уровень издержек, одно определение универсума) — это вывод жёсткой модели; он считается свидетельством, только если выдерживает заранее заявленное семейство малых возмущений (см. [knowledge/soft-models-and-optimization.md](knowledge/soft-models-and-optimization.md)). Поэтому результаты здесь читаются как stable-pass, stable-fail или unstable; неустойчивый результат — это «находки нет». Зафиксированные случаи неустойчивости в этом файле: правило составного фактора с t 3.67 на панели выживших и 1.42 на point-in-time панели (раздел 8.5), невоспроизведённые метки в единицах волатильности шага 12 в шаге 17 (раздел 6.7), качание AUC на 0.08 от удержания 20% обучающих строк (раздел 6.4) и смена знака книги ridge long-short при более высоком займе (раздел 8.6). Параметр, подобранный на историческом оптимуме, лежит на краю области устойчивости: пример — немонотонный обрыв лимита экспозиции (раздел 5.7); новые исследования приводят выбранное значение вместе с соседями по сетке и помечают его как граничный оптимум, если сосед теряет больше половины реализованного P&L или меняет его знак.

## 2. Аппаратура

**Вселенная и данные.** Торговая вселенная: 17 тикеров из `config.sandbox.yaml` (18 вместе с DATA, который был снят с живой торговли 2026-09-21, потому что его нельзя шортить). Цены: дневные свечи MOEX ISS (ISS также публикует выходные сессии по акциям, тогда как IMOEX по выходным не рассчитывается, что важно для привязки меток по времени, раздел 6.2). Обучающие наборы: `exportdataset` с 2024-01-01, если не указано иное; широкие наборы используют доску TQBR (262 обыкновенные и привилегированные акции) с point-in-time фильтром ликвидности (скользящая медиана 20-дневного оборота не менее 10 миллионов RUB). Исследовательские прогоны выполняются на ai-box (`~/moex-research`), отдельно от каталога развёртывания.

**Движок.** `internal/backtest` — это живой путь без сети: признаки на день `d` строятся по свечам `[:d]`, вход по `candles[d+1].Open`, переоценка по `candles[d].Close`, тот же `risk.HardenedGate`, один хронологический портфельный цикл (поэтому kill switch по просадке 3% и дневной лимит убытка 0.5% видят агрегированную кривую капитала; kill switch блокирует новые входы и не ликвидирует позиции). Живые признаки используют только закрытые дневные бары (`closedDailyCandles`, `closedBarReturnPct`); до этого исправления 12 из 18 развёрнутых признаков были нулевыми в живом контуре, потому что lookback составлял 10 дней.

**Preflight.** Живой гейт воспроизводит последние 90 дней с издержками спреда и проскальзывания, оценивает **реализованный** P&L, требует `preflight.min_closed_trades` раньше `preflight.min_net_pnl` и логирует SHA-256 релевантной для гейта конфигурации.

**Тестируемый рецепт («abs-10d»).** Абсолютная метка форвардной доходности на 10 баров с мёртвой зоной 0.5%, 18 колонок цены/потока плюс новости (порядок из 28 имён признаков), усреднение LightGBM + XGBoost + логистической регрессии, пороги 0.60/0.40. Эмбарго в 10 дней удаляет обучающие строки, дата метки которых заходит в тестовое окно (purged-контроль). Инструменты отчётности: `Result.Markdown()`, HTML-tearsheet (`-tearsheet`), `cmd/walkforward` (скользящие или якорные окна, сшивка агрегированного капитала), `period_returns.csv` по окнам с SHA-256 для матрицы PBO.

**Синтетическая книга со 100% шортов (2026-09-30)**, SELL на каждом баре и BUY на последнем: лимит 0 +51381 (1581 сделка, max DD 5.83%, 18 имён); 30000 +4981 (2 сделки, 0.86%); 45000 +5864 (3, 1.04%); 60000 +8831 (4, 0.87%); 90000 +11484 (6, 1.68%). Безлимитный контроль «всё в шорт» нарушает просадку 3% сам по себе (5.83%), поэтому живой убыток 2026-09-30 (17 шортов, нетто около -210k, -4.53 RUB реализованных на 60 сделках) был вызван не отсутствием лимита.

Регрессия: сетка 100% шортов воспроизводится точно (лимит 0 +51381.37, 1581 сделка, 5.83%; 30000 +4981.30, 2, 0.86%; 45000 +5863.69, 3, 1.04%; 60000 +8830.73, 4, 0.87%; 90000 +11483.63, 6, 1.68%); промежуточная реализация с добавлением на уровне всей книги сводила ограниченные строки к 0 закрытых сделок, блокируя завершающий ордер выхода в ноль (`TestHardenedGateMaxExposureAllowsReducingOrder`). Живой контур сохраняет `max_net_exposure: 0`.

### 6.10 Объяснимость сигналов (2026-10-18)

### 9.2 Диагностика перекоса в SELL и guard вне диапазона (2026-10-18)

Данные: аудит-события `trader-sandbox.db` 2026-09-16..10-18, около 38.3 тыс. решений после исправления маскирования новостей. После исправления около 3600-4200 HOLD и 460-1200 SELL в день, 0 BUY; причины HOLD: `out_of_range` 50-60%, `model` около 30%, SELL около 14%; корзины вероятностей: < 0.40 около 31%, [0.40, 0.60] около 69%, >= 0.60 0.11% (42 решения, все VTBR).

- **Находка про guard.** 100% блокировок `out_of_range` после исправления приходятся на `event_dividend` с z = 14..38, хотя развёрнутый артефакт несёт mean 0, std 1, коэффициент 0 для всех восьми событийных признаков и обоих тематических сигналов, и ни одно дерево их не использует. Guard запретил would-SELL 7138, would-BUY 42 и would-HOLD 14861. Исправление (`ae6ffdd`: пропускать признаки с логистическим коэффициентом 0, которые не использует ни одно дерево; тест `TestEnsembleIgnoresUntrainedEventFeatures`) было написано и затем откачено (`dcb601d`, см. ниже); запрет действует вживую.
- **Воспроизведение офлайн.** Реплей развёрнутой модели с исправленным guard за 2026-10-10..10-18 (136 решений): 95 HOLD / 41 SELL / 0 BUY (доля SELL 30.1% против 32.2% вживую до guard): перекос воспроизводится из данных и модели, это не дефект обслуживания. Свежая модель (обучена до 2026-09-16) даёт 94 / 39 / 3 BUY (доля BUY 2.2%): небольшая составляющая устаревания в хвосте BUY.

Эта атрибуция **не подтверждена**: две сборки `cmd/backtest` с изменением guard и без него дают идентичный вывод реплея до последней цифры (окно до 10-18: -2467.25, 117 сделок; до 10-17: +1209.23, 118 сделок); живой гейт выдал тот же -4859.13 как с исправленным бинарником, так и без; «+602.32 на том же окне» относилось к более раннему гейту с началом окна 07-19. Prometheus-метрики живого трейдера (`internal/metrics/metrics.go`, подключены через `internal/orchestrator` и `cmd/trader`; `moex_trader_inference_duration_seconds` переименована из `llm_inference_duration_seconds`, потому что конвейер — модель, а не LLM):

| метрика | тип | метки | источник |
|---|---|---|---|
| `moex_trader_inference_duration_seconds` | histogram | - | генерация сигнала оркестратором |
| `signals_generated_total` | counter | - | оркестратор |
| `risk_rejections_total` | counter | `reason` | решение риск-гейта |
| `executor_skips_total` | counter | `reason` | одобренные решения, пропущенные исполнителем |
| `signal_probability` | histogram | - | вероятность модели за опрос |
| `candle_age_seconds` | gauge | `ticker` | возраст новейшей загруженной свечи |
| `feature_psi` | gauge | `feature` | предупреждения монитора дрейфа |
| `position_notional` | gauge | `ticker` | знаковая экспозиция по тикеру (RUB) |
| `gross_exposure` | gauge | - | сумма модулей номиналов по тикерам (RUB) |
| `lease_held` | gauge | - | 1, пока процесс держит торговую аренду |
| `var_95`, `var_99`, `es_95`, `es_99` | gauge | - | 1-дневные исторические VaR/ES текущей книги (RUB), трейлинговые доходности за 250 дней (`internal/risk/var.go`), только мониторинг, также одна строка в ежедневном дайджесте Telegram |
| `incident_shorts_total` | counter | `ticker` | решения SELL, выданные новостным гейтом во время инцидента (не каждое становится исполнением) |
| `news_exit_total` | counter | `ticker`, `reason` | первое решение о выходе для позиции, открытой по новости (`stop_loss`, `take_profit`, `time_exit`); каждое также пишет строку `audit_events`, стадия `news_exit`, со входом, пиком и результатом для подбора параметров в `docs/plans/20261010-news-exit-tuning-and-buy-side.md` |

Алерты Telegram (`internal/alert/telegram/watch.go`), каждый с периодом охлаждения:

| алерт | триггер | порог по умолчанию | охлаждение по умолчанию |
|---|---|---|---|
| коллапс вероятностей | более 90% из последних N вероятностей внутри [0.45, 0.55] | N = 20, доля 0.9, диапазон 0.45-0.55 | 1h |
| устаревшие свечи | возраст свечи выше порога во время торговой сессии | 24h (конвейер дневных свечей) | 1h |
| превышение PSI | предупреждение монитора дрейфа выше настроенного порога PSI | `drift_psi_threshold` 0.2 | 1h |

Значения по умолчанию берутся из `config.alerts` (`probability_collapse_window`, `stale_candle_age`, `cooldown`); отрицательные значения отклоняются, а отправители не делают ничего без учётных данных Telegram.
