## Гипотезы (зафиксированы до запуска)

- **I1. Концентрация по дням.** Реализованный P&L гейт-реплея сосредоточен в небольшом числе дней; выкатывание этих дней из окна и переводит результат в минус. Измерение: дневная реализованная серия (period_returns.csv) гейт-формы реплея; доля P&L топ-10 дней; скользящая 90-дневная сумма по till.
- **I2. Деградация свежих сделок.** Средний реализованный P&L на закрытую сделку по месяцу закрытия падает к октябрю. Измерение: среднее/медиана по закрытым сделкам, сгруппированным по месяцу, с бутстрепом по датам (описательно).
- **I3. Ожидание самовосстановления.** Если I1 подтверждается и прибыльные дни уже ушли из окна, гейт сам по себе не «пройдёт снова» — проверяется расчётом скользящей суммы вперёд на известной серии (где есть данные) и прогнозом границы: пройдёт ли окно выше порога при текущем темпе свежих дней.

## Протокол

- Чтобы воспроизвести гейт, в `cmd/backtest` добавляются флаги `-max-net-short`/`-max-net-long` (пасс-тру в существующий engine config `MaxNetShort`/`MaxNetLong`, который префлайт уже передаёт); тест парсинга флагов в том же коммите.
- Реплеи: `./backtest -config config.sandbox.yaml -tickers <17> -from <till−90д> -till <till> -deposit 1000000 -max-lots 1000 -commission-rate 0.0005 -spread-pct 0.0005 -spread-db trader-sandbox.db -slippage-pct 0.0005 -borrow-pct-day 0.00005 -target-notional 15000 -max-net-short 90000 -max-net-long 90000 -lookback-days 0 -signal-source ensemble -ensemble-path ensemble_model.json -wf-dir <dir>` для till ∈ {10-14, 10-15, 10-16, 10-17, 10-18}. Без `-news-history` (как в гейте).
