# Отсев убыточных тикеров: walk-forward и сравнение со случайным отсевом, `cmd/tickerselect`

Английская версия: [20261022-ticker-selection-check.md](20261022-ticker-selection-check.md) — каноничная.

Статус: выполнен 2026-10-22; критерии зафиксированы до первого запуска. Вердикт: неотличимо от случайного отсева, фильтр не принимается (`docs/metrics.md` 8.14).

## Вопрос

Улучшает ли исключение убыточных тикеров (или «ведущих себя не по модели») живую ridge-книгу, если отбор использует только информацию, доступную в тот момент?

## Дизайн

Таблица `data/ridge_scores.csv` (17 тикеров) прогоняется на W2 (2025-03-05..2026-10-18) через `backtest.NewEngine` с теми же параметрами книги, что у `cmd/placebocheck`. W2 режется на последовательные блоки по `-block-days` календарных дней (по умолчанию 91, близко к пересчёту ridge раз в 63 торговых дня). Блок 0 только обучающий; оцениваются блоки 1..m. Позиции между блоками не переносятся; каждый блок — отдельный прогон движка, статистика — сумма реализованного P&L за вычетом borrow по блокам 1..m.

Ветви, в каждой отсекается `K` тикеров (по умолчанию 4, нижний квартиль из 17) на блок:

- FULL: все тикеры.
- WALK-FORWARD: отсечь K тикеров с наименьшим P&L (сумма `Trade.NetPnl` закрытых сделок) в блоке j-1, торговать блок j. Единственная честная ветвь.
- IN-SAMPLE (утечка, описательно): отсечь K худших самого блока j и торговать им же. Показывает, какая доля «улучшения» — чистое смещение отбора; результатом не считается.
- RANDOM: N = 200 розыгрышей, каждый независимо по блокам отсекает K случайных тикеров; итог розыгрыша — сумма по блокам. Seed 20261022 + номер розыгрыша.

Диагностика без критерия: средняя ранговая корреляция Спирмена P&L по тикерам между блоками j-1 и j (устойчивость «аутсайдеров») и как часто отсечённый тикер оказывался в нижних K следующего блока.

Ставки borrow 0.00005 и 0.00047 в день, как в placebo-проверке.

## Критерий (до запуска)

Для каждой ставки: односторонний эмпирический p = (1 + число случайных итогов не ниже WALK-FORWARD) / (N + 1).
- «Фильтр тикеров работает»: WALK-FORWARD > FULL и p <= 0.05 при 0.00047.
- «Ограничено ставкой»: то же только при 0.00005.
- Иначе: «отсев убыточных неотличим от случайного отсева»; фильтр не принимается.
Оговорки: K, длина блока и метрика отбора выбраны автором до запуска один раз и после не подбираются; при m около 5 блоков мощность низкая, поэтому отрицательный результат означает «не показано», а не «доказана бесполезность». Результат не гейт и живой путь не трогает.

## Чего не делаем

Не меняем preflight, живой путь, конфиг, `ensemble_model.json` и `data/ridge_scores.csv`; новых зависимостей нет; только флаги.
