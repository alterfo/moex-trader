# Учёт комиссий и поддержка брокера Finam

## Обзор

Два связанных пробела, найденных при разборе первой сборки:

1. **Нигде нет учёта комиссий/сборов.** У `executor.Fill` нет поля комиссии, `PaperExecutor` и `internal/executor/live.go` (Tinkoff) записывают исполнения по «сырой» цене, а `internal/verifier` восстанавливает P&L по сырым ценам исполнений. Бумажная торговля (Фаза 3) и гейт «50+ прибыльных сделок» (Фаза 4) без этого бессмысленны — сделка, бумажная «победа» по сырой цене, может оказаться реальным убытком после комиссий.
2. **Второй брокер: Finam Trade API**, выбран вместо Alfa-Investments после проверки того, что реально публично задокументировано. Finam публикует настоящую спецификацию API (`api.finam.ru` / `tradeapi.finam.ru`): REST + gRPC + WebSocket, двухшаговая авторизация токен→JWT (JWT действует 15 мин, обновляется вызовом API), выставление ордеров (market/limit/stop/stop-loss/take-profit), эндпоинты счёта/портфеля, рыночные данные в реальном времени и исторические, демо-счёт и опубликованный лимит запросов (200 запросов/мин на метод). Публичная документация Alfa неоднозначна (в основном общий банковский партнёрский API, а не явно розничный торговый API), поэтому разработка под него грозила дать правдоподобный, но нерабочий клиент. Тариф Finam «Единый дневной» также дешевле (от 0.01%), чем «Трейдер» у Alfa (от 0.014%).

Этот план добавляет учёт комиссий (независимый от брокера) и интеграцию рыночных данных и исполнения Finam, по тому же шаблону, что уже использован для Tinkoff.

## Контекст (по результатам исследования)

- `internal/executor/executor.go`: интерфейс `Executor`
  (`Execute(ctx, signal, price) (Fill, error)`), структура `Fill`, `PaperExecutor`.
- `internal/executor/live.go`: живой исполнитель Tinkoff — образец для Finam
  (тот же интерфейс, свой клиент, свои тесты на моках).
- `internal/ingestion/tinkoff/client.go`: `Config`, `Client`, `Quote`, `Candle`,
  `OrderBookLevel`, `OrderBook`, `New(ctx, cfg) (*Client, error)` — форма, которую
  повторить для `internal/ingestion/finam`.
- `internal/verifier`: читает `audit_events`, сопоставляет сигналы с исполнениями, строит
  markdown-отчёты по P&L — сейчас полностью игнорирует комиссии.
- `cmd/trader`: сейчас отказывается стартовать при `is_paper_trading: false`, потому что
  живая обвязка Tinkoff (снапшот счёта, отмена ордеров) не подключена. То же
  честное поведение отказа должно действовать для живого режима Finam, пока нет
  эквивалентной обвязки — никакого тихого обхода защит риска.
- Кода комиссий/сборов в репозитории нигде нет (подтверждено grep).

## Подход к разработке

- **Подход к тестированию**: обычный (сначала реализация, тесты в той же задаче) —
  в соответствии с первым планом.
- Все денежные поля остаются `decimal.Decimal`.
- Авторизации Finam (секретный токен → JWT, срок 15 мин) нужен путь обновления до истечения —
  обращаться как с обработкой токена Tinkoff, тестировать на моке часов/срока.
- **КРИТИЧНО: каждая задача ДОЛЖНА включать новые/обновлённые тесты.**
- **КРИТИЧНО: все тесты должны проходить до начала следующей задачи.**
- **КРИТИЧНО: обновлять этот файл плана при изменении объёма во время реализации.**

## Стратегия тестирования

- Юнит-тесты для каждой задачи; внешние HTTP/gRPC-вызовы подменяются через `httptest.Server`
  или внутрипамятные заглушки — никаких реальных сетевых вызовов, реальный токен Finam для прохождения
  тестов не нужен.
- Логика обновления авторизации получает явные тесты: токен близок к истечению — запускает обновление, просроченный
  токен на запросе запускает обновление и повтор, сбой обновления выдаёт ошибку.

## Технические детали

**Fill с комиссией:**
```go
type Fill struct {
    ID         string
    Ticker     string
    Action     domain.Action
    Lots       int
    Price      decimal.Decimal
    Commission decimal.Decimal
    ExecutedAt time.Time
}
```

**Поток авторизации Finam (по публичной документации):**
1. Получить долгоживущий секретный токен на портале токенов Finam (вручную,
   «После завершения»).
2. Обменять его на JWT методом `Auth` API; JWT действует 15 минут.
3. Прикладывать JWT заголовком `Authorization` к каждому запросу; обновлять заранее
   до истечения или реактивно при 401.

**Дополнения конфига:**
```yaml
commission:
  broker: "finam"
  rate: "0.0001"   # 0.01%, Finam "Единый дневной"
broker: "finam"     # paper | tinkoff | finam
finam:
  base_url: "https://api.finam.ru"
  secret_token: ""  # from env / .env, never committed
```

Секция конфига `finam` реализована в `internal/config` (`base_url` с
переопределением `MOEX_TRADER_FINAM_BASE_URL`; `secret_token` только из окружения через
`MOEX_TRADER_FINAM_SECRET_TOKEN`) и отражена в `config.example.yaml`.
