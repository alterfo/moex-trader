# План: макро- и фундаментальные признаки в модели, учёт позиций и P&L в риск-гейте

Статус: EXECUTED 2026-10-10. Часть C и обвязка признаков выпущены; предрегистрированная оценка не нашла прироста AUC (docs/metrics.md «Macro and dividend-yield features»), поэтому модель для развёртывания не переобучалась. Решено с пользователем: фундаментальные и макро-данные становятся признаками модели; позиции счёта и P&L идут только в риск-гейт, никогда в модель.

## 1. Почему такое разделение

- У макро и фундаментальных данных есть история, поэтому ансамбль можно обучать и проверять walk-forward на них. У позиций счёта и P&L нет истории до появления песочничного счёта, а обучение на собственных исполнениях бота протекает в метку (позиция следует за прошлыми сигналами). Это ограничения, а не предикторы.
- Инцидент 2026-10-10 (`docs/knowledge/model-quality-history.md`, «Live news_count train/serve skew») показывает режим отказа любого признака, который есть в лайве, но отсутствует в обучении. Каждый новый признак ниже должен присутствовать в истории `exportdataset`, в живом Builder и в бэктесте, порождаясь одним и тем же кодовым путём.

## 2. Часть A: макро-признаки (модель)

Кандидаты, каждый как дневной ряд, доступный point-in-time:

| Признак | Источник (проверить перед построением) | Примечание |
|---|---|---|
| Доходность IMOEX 1д/5д/21д, IMOEX против MA50 | история индекса MOEX ISS | уже выгружается для меток избыточной доходности |
| Доходность USD/RUB (или CNY/RUB) 5д/21д | валютный рынок MOEX ISS | проверить площадку и глубину истории |
| Доходность Brent 5д/21д | непрерывный контракт FORTS MOEX ISS или индекс | проверить; запасной вариант — отказаться |
| Уровень ключевой ставки ЦБ и последнее изменение | cbr.ru | сначала проверить доступность из этой сети; ступенчатый ряд, небольшой |

Правила: макро-значение на дату d использует только данные, опубликованные к закрытию d-1 (без заглядывания вперёд). Макро-признаки кросс-секционно одинаковы в данный день, поэтому могут лишь сдвигать базовую частоту и взаимодействовать с признаками тикера в деревьях; не ждать, что они ранжируют тикеры. Этот предел указать в результате.

## 3. Часть B: фундаментальные признаки (модель)

- Кандидаты: дивидендная доходность (существующий календарь `internal/dividends` плюс цена), P/E, P/B, чистый долг / EBITDA.
- Открытый блокер: нет проверенного point-in-time источника фундаментальных данных. Сначала проверить фундаментальные данные активов T-Invest API и любые эндпоинты MOEX. Фундаментальные данные, пересмотренные или взятые на сегодня, протекают будущим при присоединении к старым датам; использовать только значения с датой отчёта, иначе отказаться от признака.
- Дивидендная доходность из существующего календаря — единственный кандидат, не требующий нового источника; строить её первой.

## 4. Часть C: позиции и P&L в риск-гейте (не в модели)

Уже есть: лимит валовой экспозиции (`risk.max_net_exposure`, `sector_caps`), дневной убыток, kill switch по просадке, брейкер по тикеру. Отсутствует и мотивировано книгой с чистым шортом ≈-219k, выросшей, пока IMOEX рос:

- Лимит чистого направления: отклонять ордера, толкающие знаковую чистую экспозицию за `risk.max_net_short` / `risk.max_net_long` (RUB, 0 = выключено).
- Охрана макро-режима (опционально, под флагом конфига): блокировать новые шорты, пока IMOEX выше MA50 и растёт, зеркально для лонгов. Оценить в бэктесте до включения.
- Показывать текущую чистую экспозицию и дневной P&L в payload аудита `risk_gate` для диагностики.

## 5. Порядок работ и гейты

1. Сначала лимит чистого направления из части C: переобучение не нужно, сразу ограничивает ущерб. Регрессионный тест, воспроизводящий книгу целиком из SELL.
2. Признак дивидендной доходности (без нового источника), затем макро-ряды. Добавлять в `ToVector` одним изменением вместе с `exportdataset`, `FEATURES` в `scripts/export_ensemble.py`, `scripts/compare_models.py` и parity fixture.
3. Переобучение на ai-box, затем purged walk-forward (`-embargo-bars 10`), сравнить AUC и реализованный P&L через `cmd/strategyvalidation`, каждое число записать в `docs/metrics.md` тем же коммитом.
4. Сначала запустить новый ансамбль как `model.challenger_ensemble_path` (тень); `cmd/challengercompare` — только свидетельство.
5. Продвижение в лайв требует гейта purged walk-forward и явного согласия пользователя (без авто-замены, см. AGENTS.md).

- Часть C выпущена как `risk.max_net_short` / `risk.max_net_long` (`net_direction_exceeded`), в `config.sandbox.yaml` задано 90000.
- Признаки: `internal/macro` (загрузка ISS + cbr.ru, CSV-хранилище в `data/macro`, point-in-time `At(day)` только по закрытиям строго до дня решения), `features.NewMarketEnricher` (добавляет `FeatureContext.Extra`), векторы модели по имени через `model.ToVectorFor(feature, model.FeatureOrder)`. Модель, у которой `feature_order` требует отсутствующий признак, громко роняет решение вместо чтения нуля.

## 8. Предрегистрированная оценка (зафиксирована до первого запуска)

- Данные: `exportdataset -from 2024-01-01 -till 2026-10-09 -split 2026-06-18 -horizon-days 10 -deadband-pct 0.5 -label-mode absolute -macro-dir data/macro`, без истории новостей, FX-тикеры исключены, запуск на ai-box (`~/moex-research`).
- Протокол: существующий `evalh.py` `wf()` (purged walk-forward с расширяющимся окном, тестовые фолды по 63 дня с 2025-04-01, `label_date < fold start`, усреднение LightGBM + logistic).
- Ветви (все на одних строках): A = 15 ценовых/потоковых колонок (база `docs/knowledge/model-quality-history.md`), B = A + `div_yield_ttm_pct`, C = A + 9 макро-колонок, D = A + B + C.
- Основная метрика: объединённый AUC; вторичные: средний AUC по фолдам и число фолдов с AUC > 0.5.
- Критерий успеха для признания кандидатом на замену: ветвь превосходит A минимум на +0.010 объединённого AUC И у неё большинство фолдов > 0.5, И реализованный P&L через `cmd/backtest -signal-source=ensemble -macro-dir data/macro` на тех же окнах не падает ниже развёрнутого ансамбля. Всё слабее фиксируется как отсутствие эффекта. Прохождение — только свидетельство: развёртывание требует явного согласия пользователя.
