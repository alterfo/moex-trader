# Признак сигнала переговоры/санкции

## Обзор

Рыночный тезис, на котором строится план: российский рынок сейчас торгуется на новостном потоке о
скидке за санкции/украинских переговорах, а не на цене нефти или ключевой ставке ЦБ.
Карта сигналов: (a) содержательный прогресс переговоров → сильный risk-on; (b) реальное применение
100% пошлин против покупателей российской нефти → стресс; (c) базовый сценарий — боковик
на дивидендах/снижении ставки со всплесками волатильности на каждый заголовок про Уиткоффа.

Ни «нефть», ни «ставка» сейчас не являются явными признаками этой модели (понижать нечего),
и «переговоры» тоже (повышать пока нечего) — что реально существует сегодня, см. «Технические
детали». Этот план добавляет **знаковый признак сигнала переговоры/санкции**, исправляет
рассогласование тональности между лайвом и обучением, которое сейчас мешает ему
корректно работать вживую, и оставляет результат в развёрнутом ансамбле только если он проходит
ту же планку доказательств по AUC/бэктесту, которую репозиторий уже применяет к любому другому
добавляемому признаку.

## Контекст (по результатам исследования)

- `news_classifier.json` (корень репозитория) — плоская логистическая регрессия мешка слов
  по токенам заголовков (`internal/model/newsclassifier.go`): у каждого токена, включая
  `санкции`, `нефть`, `ставка`, `переговоры`, один независимый скалярный коэффициент,
  питающий единую сигмоиду, которая предсказывает направление будущей избыточной доходности относительно IMOEX. Группировки
  по темам/категориям внутри нет.
- Сегодня существуют два несвязанных пути тональности:
  - **Лайв/бэктест**: `internal/features/builder.go` (`aggregateNewsSentiment`/
    `articlePolarity`) оценивает заголовки зашитым лексиконом ключевых слов
    (`positiveKeywords`/`negativeKeywords`). `news_classifier.json` он не загружает.
    Лексикон зашивает `санкц` как всегда негативное независимо от контекста — заголовок
    о *снятии* санкций сегодня получил бы негатив, наоборот карте сигналов этого плана.
  - **Офлайн/обучение**: `cmd/newsscore -method=model` оценивает исторический
    `news_history.jsonl` через `news_classifier.json` → `model.LoadFinanalysNewsHistory` →
    `AggregateDailySentiment` (`internal/model/newsimport.go`) → слоты признаков `news_sentiment`/
    `news_count`, которые потребляет `cmd/exportdataset -news-history`.
  - По AGENTS.md (запись о переобучении с новостями от 2026-09-17), развёрнутый `ensemble_model.json`
    обучен на истории, оценённой классификатором, но живой инференс всё ещё использует лексикон
    ключевых слов — известное рассогласование лайв/обучение, которое этот план устраняет как предпосылку.
- Единственная структура, похожая на тему, — `event_sanctions`, один из 8 бинарных regex-флагов
  в `internal/features/events.go` (`DetectEvents`). По AGENTS.md, эти 8
  признаков `event_*` сейчас *исключены* из развёрнутой 18-признаковой модели: при
  `colsample_bytree`/`feature_fraction` 0.8 они разбавляют выбираемые колонки и ухудшают
  результат walk-forward (18 колонок = +110741₽; 26 колонок = +80716₽; colsample 1.0 =
  +87823₽). `event_negotiations` не существует.
- Порядок вектора признаков задан один раз в `internal/model/features.go`
  (`defaultFeatureOrder`/`ToVector`) и должен оставаться зеркальным в `cmd/exportdataset/main.go`,
  `scripts/export_ensemble.py` (`FEATURES`) и `scripts/compare_models.py` (`FEATURES`) —
  обновлять все четыре вместе (правило конвейера признаков AGENTS.md).
- **Замечание о параллельной сессии**: этот план и сейчас выполняющийся запуск ralphex по
  `docs/plans/20260917-strategy-validation-implementation-plan.md` оба
  трогают `internal/features/builder.go`, `internal/model/features.go` и
  `cmd/exportdataset`. По правилу AGENTS.md о запрете параллельных правок, **не запускать ralphex по
  этому плану, пока тот запуск ещё активен** — сначала убедиться, что он завершён (проверить
  `.ralphex/progress/progress-20260917-strategy-validation-implementation-plan.txt` и
  `git log`) и дерево чисто.
- `docs/metrics.md` (создан Задачей 17 другого плана, если она выполнена раньше) —
  общий единый источник истины по числам бэктеста — дописывать в него, а не создавать
  конкурирующий файл.

- **Гейт доказательств (из Обзора)**: новые признаки остаются в развёрнутом
  ансамбле только если сравнение «с/без» из Задачи 6 показывает измеримое улучшение
  валидационного AUC и/или реализованного P&L walk-forward — в соответствии с дисциплиной, уже

- Обновлять этот план, если реализация отклоняется от исходного объёма.

## Стратегия тестирования

- Юнит-тесты обязательны для каждой задачи: новые regex-детекторы, новый код агрегации,
  новая оценка в лайве через классификатор и проверка согласованности порядка признаков.
- После каждой задачи запускать полный набор тестов проекта, прежде чем идти дальше.
- Шаг переобучения/сравнения (Задача 6) проверяется числами AUC/бэктеста, а не

  для логики вычислений.

## Технические детали

- **Детекция темы переговоров**: новый regex в `internal/features/events.go` рядом с
  существующим шаблоном `event_sanctions` (`санкц\w*|ограничен\w*\s*торг|блокиров\w*`).
  Кандидаты терминов: `переговор\w*`, `уиткофф`, `witkoff`, `мирн\w*\s*(план|соглашен\w*)`,
  `прекращен\w*\s*огня`, `урегулирован\w*`. Это только детекция темы (касается ли заголовок
  переговоров вообще) — направление кодировать в ней не нужно.
- **Направление берётся из классификатора, а не из знака ключевого слова**: для любого заголовка, который
  совпал с regex переговоров или regex санкций, брать собственный балл полярности `news_classifier.json`
  для этого заголовка (уже сигмоидно отображённый в `[-1,1]`) вместо
  зашитого знака лексикона. Для этого живой инференс должен реально загрузить и вызвать
  классификатор (`model.NewsClassifier.Scorer()`), чего сегодня не делает — подключение
  этого — Задача 2, и она попутно исправляет баг «`санкц` всегда негативно» как побочный эффект,
  поскольку выученные коэффициенты классификатора полностью заменяют фиксированный знак лексикона
  для этих двух новых признаков.
- **Новые поля признаков**: `negotiations_signal`, `sanctions_signal` — дневное среднее
  балла классификатора по заголовкам, совпавшим с regex каждой темы в этот день, `0`, когда
  подходящих заголовков нет. Добавить оба имени в конец порядка признаков (не нарушать
  существующий 26-именной порядок и существующий бинарный слот `event_sanctions`).
- **Историческая/офлайн-агрегация**: повторить `AggregateDailySentiment`
  (`internal/model/newsimport.go`) с фильтром по regex темы, чтобы `cmd/exportdataset
  -news-history` мог заполнить оба новых сигнала задним числом из `news_history.jsonl`.
- **Оговорка о разреженности из AGENTS.md**: существующие 8 событийных признаков
  разрежены (541 из 15187 строк ненулевые при последней проверке) и всё равно проиграли
  18-признаковому набору даже при частично реальных событийных данных. Ожидать, что `negotiations_signal`
  будет столь же разреженным, пока в `news_history.jsonl` не накопится больше заголовков об украинских переговорах
  — именно поэтому существует гейт доказательств Задачи 6.
