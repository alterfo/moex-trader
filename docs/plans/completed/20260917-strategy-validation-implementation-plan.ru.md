# План реализации валидации стратегии

## Обзор

Развёрнутый ансамбль abs-10d (18 признаков, пороги покупки/продажи 0.60/0.40, 15000₽ на
позицию, удержание до разворота, 18 тикеров, песочница T-Bank) никогда не проходил
валидацию настоящим гейтом, эквивалентным лайву, или формальной статистикой. Этот план реализует
консенсус двух сессий opencode (взят из `docs/plans/completed/20260917-strategy-validation-action-plan.md`,
который этим планом не изменяется) для решения по заранее зарегистрированным критериям о том, есть ли у
системы доказуемое преимущество, прежде чем рассматривать любое решение о реальных деньгах.

Работа идёт четырьмя группами, по порядку: дешёвые тесты на опровержение, которые могут убить стратегию
за полдня; блокеры движка, из-за которых числа лайва и бэктеста расходятся; формальная
статистика преимущества (скорректированный на дефляцию Sharpe, PBO, декомпозиция по режимам, заморозка OOS); и инфраструктура
издержек/риска (займ, спред по тикеру, сохранение walk-forward, атрибуция, мониторинг дрейфа,
единые метрики). Критерии go/no-go для реальных денег перечислены в
«После завершения» — они требуют решения человека, а не автоматической проверки, и
намеренно не закодированы как чекбоксы Задач.

## Контекст

- Обе сессии opencode согласны: **сегодня никаких реальных денег.** Песочница продолжает работать как
  сбор данных и проверка инфраструктуры.
- Утверждение левой сессии «AUC 0.52 => P&L неотличим от удачи» уточнено: AUC
  ранжирует всё распределение меток, тогда как стратегия торгует только хвосты
  распределения вероятностей, а заголовочный Sharpe отчасти является артефактом почти плоской
  дневной кривой (много дней без экспозиции). Скорректированная формулировка: **преимущество не опровергнуто, а
  бремя доказательства лежит на хвостах и на декомпозиции по бете/режиму**, а не «доказуемо
  невозможно».
- Гипотеза правой сессии «+110742₽ могут быть бетой, пойманной трендовым фильтром в одном
  режиме» сама по себе остаётся рассказом, пока не измерена — это становится Задачей 9 (2.3).
- Блокеры, найденные в коде (подтверждены обеими сессиями, со ссылками файл:строка): живой вектор признаков
  строится иначе, чем вектор обучения/бэктеста; лимит kill-switch/дневного убытка в бэктесте — мёртвый код, а
  в лайве он по тикеру, а не на уровне портфеля; preflight судит по MTM с нулевыми издержками и порогом 0₽;
  5-минутный опрос плюс исполнитель целевой позиции вызывают шум ребалансировок.
- Применяется инвариант AGENTS.md: судить о стратегиях по **реализованному** P&L, а не по MTM.
- Исходные артефакты дебатов (`critique-left.md`, `rebuttal-right.md`, `plan-additions-right.md`)
  были временными рабочими файлами, не закоммиченными в репозиторий.

## Подход к разработке

- Подход к тестированию: обычный (писать тесты вместе с каждой задачей, строгий TDD не требуется).
- Каждую задачу завершать полностью — включая её тесты и обновление документа метрик — до перехода к
  следующей.
- **Точка паузы после Задачи 2** (тесты на опровержение Шага 0): рассмотреть результаты tail-precision
  и бенчмарка моментума с пользователем, прежде чем продолжать. Задача 3 и далее (исправления движка Фазы 1)
  стоит делать независимо от исхода Шага 0 по исходным дебатам, но
  переход к Фазам 2/3 (формальная статистика, инфраструктура издержек) должен следовать
  обдуманному решению, а не запускаться автоматически, если Шаг 0 опровергает стратегию.
- Обновлять этот план, если реализация показывает, что объём надо изменить.

## Технические детали

Известные блокеры кода и указатели (из исходных дебатов, подтверждены обеими сессиями):

- **Паритет признаков**: лайв строит признаки из массива свечей, включающего текущий
  незакрытый дневной бар и внутридневной `LastPrice` (`ingest.go:75-94`, `builder.go:76-102`);
  обучение/бэктест используют только закрытые бары с `LastPrice = prev close` (`engine.go:378-386`).
- **Портфельный риск-гейт**: бэктест передаёт эквити одного тикера и никогда не задаёт
  `DayStartEquity` (`engine.go:442-452`, `gate.go:217-235`), поэтому лимиты просадки 3% и
  дневного убытка 0.5% никогда не срабатывают в бэктесте, хотя в лайве проверяются по портфелю.
  Агрегированная кривая уже существует (`aggregateCurves`, `engine.go:707-723`).
- **Preflight**: спред/проскальзывание не передаются в preflight-бэктест
  (`cmd/trader/main.go:770-822`); `min_net_pnl` по умолчанию `"0"`; `NetPnl` — это MTM
  (`FinalEquity - Deposit`, `engine.go:696`), что противоречит инварианту AGENTS.md
  «реализованный против MTM».
- **Ребалансировка/шум сигнала**: исполнитель целевой позиции (`orchestrator.go:165-210`) не имеет
  гистерезиса ни по размеру ребалансировки, ни по выходу из полосы сигнала.
- **Модель спреда**: модель половинного спреда уже существует (`engine.go:481-490`) и может быть
  переиспользована для работы по спреду на тикер.
- Вероятности для теста tail-precision берутся из существующего флага `-cache`
  (`cmd/backtest/main.go:78`, `ensemble.go:122`).

Предрегистрированные пороги, перенесённые из исходных дебатов (используются в более поздних задачах, не
выводятся заново): окно теста tail-precision/моментума ≈136 решений (приближение до
сохранённых по кварталам моделей Задачи 13); гистерезис ребалансировки ≥1 лот и >5% отклонения
номинала (точный X% регистрируется до запуска Задачи 6); порог множественной проверки t≈3-4
(Harvey & Liu) для Задачи 7; шоки gap-stress -10%/-20% для Задачи 8; стресс займа в шорт
0.005%/день для Задачи 11; проверка сброса kill-switch эквити ≥1.5x max_notional для
Задачи 18.

## После завершения

*Пункты, требующие ручного вмешательства и суждения человека — без чекбоксов, только
информационные. Ничто из этого не должен решать автоматически исполняющий агент.*

**Предрегистрированные критерии go/no-go для реальных денег** (заданы сейчас, до каких-либо новых прогонов;
их ослабление требует нового явного решения):

1. Выполнены критерии выхода из Фазы 1 (лайв ≡ бэктест, портфельный гейт, усиленный preflight — Задачи
   3-6).
2. Шаг 0 пройден: tail-precision значимо превосходит базовую частоту, а модель превосходит
   бенчмарк моментума за вычетом издержек (Задачи 1-2).
3. >=2 кварталов замороженного OOS с **реализованным** P&L > 0 при консервативных издержках
   (спред+проскальзывание 0.05%+0.05%, займ в условиях стресса).
4. DSR > 0.95, PBO < 0.2 (числа попыток из реестра Задачи 7).
5. Положительная альфа с t > 3 после вычета бенчмарков IMOEX и моментума; спецификация
   регрессии и формула SE фиксируются заранее, а число испробованных спецификаций
   записывается в реестр.
6. Присутствует хотя бы один небычий OOS-квартал (иначе результат помечается как бета-
   риск и не проходит).
7. Расхождение лайв-бэктест остаётся в заранее заданном допуске за >=1 месяц работы
   песочницы.
8. Полное прохождение `docs/GO_LIVE_CHECKLIST.md`, включая учения kill-switch в песочнице.
9. Все деньги остаются `decimal.Decimal` (GO_LIVE_CHECKLIST #1); `float` только в
   статистике/построении графиков.

**Явные не-цели:**

- Никаких новых признаков, пока не решена проблема ширины данных (осцилляторы уже дали
  лишь ±0.005 AUC).
- Никакой настройки порогов/номинала на тех же 6 окнах — это схема проклятия победителя.
- Никакого автопереобучения или горячей замены модели (отклонено 2026-09-16; без изменений).
- Никакого реального исполнения без полного прохождения чек-листа и нового явного согласия.

**Открытые вопросы:**

- Ликвидировать ли позиции при срабатывании kill-switch (лайв сейчас не ликвидирует) — решается
  в Задаче 4 (1.2); если ответ останется «нет», тест gap-stress (Задача 8) — это
  компенсирующий контроль.
- Точная ставка займа и взимает ли её счёт песочницы вообще — Задача 11 (3.1)
  измеряет это, а не гадает.
- Превосходит ли tail-precision базовую частоту — неизвестно, пока не выполнена Задача 1 (0.1); исходные
  дебаты называют это самым информативным экспериментом плана.
