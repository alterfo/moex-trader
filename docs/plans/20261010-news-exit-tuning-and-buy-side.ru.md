# Новостной выход: подбор параметров, реплей-бэктест, покупка

Статус: PLANNED (создан 2026-10-10). Направление: `docs/VISION.md`. Контекст: `docs/knowledge/news-and-events.md` («News-position exit»).

## 1. Подбор параметров выхода (заблокирован данными)

- Значения по умолчанию: арм тейк-профита 1.5% / трейл 0.7% / стоп 2.5% / макс. удержание 24ч / кулдаун 48ч масштабированы от CAR[0,+1] инцидента ~ -2.3% при N=12, а не подобраны.
- Триггер: >= 30 живых шортов по инцидентам в истории `news_trade_state` и `incident_shorts_total`. До этого числа не трогать.
- Протокол (фиксируется до просмотра): сетка тейк-профит {1,1.5,2}%, трейл {0.5,0.7,1}%, макс. удержание {12,24,48}ч; метрика = средняя доходность на сделку за вычетом комиссии с бутстрэп-ДИ по датам; набор параметров выбирается по нижней границе ДИ, а не по среднему; полная сетка пишется в `docs/metrics.md` тем же коммитом.
- СДЕЛАНО: счётчик `news_exit_total{ticker,reason}` и аудит-событие `news_exit` на каждую сделку (вход, пик, результат, время удержания) накапливают данные для этого шага.

## 2. Реплей-бэктест шорта по инциденту и выхода

- Реплей preflight не видит новостей, поэтому у шортов нет бэктеста. `data/news_history.jsonl` (~10k строк с 2026-04) достаточно, чтобы переиграть `CountIncidentSources` по дням.
- Построить `cmd/incidentreplay`: для каждой пары тикер-день с IncidentCount >= 2 входить по открытию следующего бара, прогонять правила выхода на дневных барах (внутридневных, если доступны минутные свечи ISS), вычитать комиссию и стоимость заимствования. Логика выхода должна быть общей с `cmd/trader` (вынести функцию решения из `newsExitManager.evaluate` в пакет), чтобы реплей и лайв не могли разойтись.
- Критерий успеха, зарегистрированный заранее: средняя чистая доходность на сделку > 0 с нижней границей ДИ > -0.5%, N >= 30. Иначе `incident_short_enabled` остаётся выключенным.

## 3. Покупка

- Надёжного направления по позитивным новостям сегодня нет: лексиконный классификатор мёртв (val AUC 0.49-0.54), событийные темы эффекта не показали.
- Кандидат (из arXiv 2412.19245): оценивать заголовки предобученной моделью тональности с поддержкой русского без дообучения на ценовых метках; агрегировать по паре тикер-день; проверять аномальную доходность следующего дня механизмом `cmd/eventstudy` (с поправкой на рынок, бутстрэп по датам).
- Ограничения: ToS запрещает обучение на данных Telegram/Google News (только оценка на инференсе); на ai-box один локальный экземпляр LLM и общий GPU, поэтому запускать офлайн пакетами, никогда не в живом пути.
- Зарегистрировать протокол до первого запуска (окно, метрика, порог успеха). Только при прохождении выдавать BUY из новостного гейта; существующий менеджер выходов уже обрабатывает длинные сделки (`Short=false`), но у `noteShortEntry` пока нет длинного аналога.
- Согласовать с сессией, владеющей новостным анализатором, до правок `internal/ingestion/news`.
