# Model quality and strategy research history

Read before proposing any new feature, label, horizon, threshold, sizing rule or retrain. Most obvious ideas are already measured and rejected here.

Moved verbatim from AGENTS.md on 2026-10-09; the rules in AGENTS.md itself still take precedence.

## Model quality / current state (as of 2026-09-16)

- Ensemble (lgbm+xgb+logreg average) at buy/sell thresholds 0.60/0.40 is the live signal source (`internal/model/ensemble.go`, `ensemble_model.json`, config `model.ensemble_path`).
- Baseline classification AUC for all three underlying models is only ~0.50-0.52 on the current validation split — barely better than noise. Strong in-sample P&L (e.g. +8566₽ over 365d) next to negative out-of-sample P&L (-497₽ on the actual validation window) is a data-scarcity/overfitting symptom, not a bug — confirmed independently via an AUC comparison and via the sandbox preflight gate correctly refusing to start.
- Adding features (MACD/Stochastic/Williams %R oscillators, Bill Williams Alligator) did **not** move validation AUC beyond noise (±0.005) — the bottleneck is data volume/breadth, not feature engineering. Priority order: (1) widen the ticker universe for more training rows, (2) more history where available, before (3) more features or threshold tuning. Walk-forward threshold tuning is premature while baseline AUC sits at ~0.5 — it would just fit noise.
- Real T-Bank commission tariff is **"Трейдер": 0.05% per trade** (`commission.rate: "0.0005"` in `config.yaml`/`config.example.yaml`). It was previously mis-configured at 0.3% (the older "Инвестор" tariff) — if you see `0.003` anywhere, it's stale.
- **Rejected after evidence gate (2026-09-18)**: `negotiations_signal` + `sanctions_signal` (20-feature topic variant) do not clear the deployment bar. Validation ensemble AUC 0.5098 vs baseline 0.5084 (+0.0014, within the ±0.005 noise band); 6-quarter realized P&L +103739.34₽ vs +101246.75₽ (+2.5%) but window-mixed and max DD 3.55% vs 3.52%. The deployed `ensemble_model.json` stays on the 18-feature recipe but carries the 28-name feature order with zero coefficients for the two topic columns so live inference still passes the feature-order check. The archive only covers 2026-08-14..09-17, so the new signals are zero in every training window — early-window differences are colsample dilution from extra zero-variance columns, not learned signal. Revisit only after a richer historical news backfill.
- **Horizon label noise (weekend phantom bars) REJECTED as AUC-ceiling explanation (2026-10-02)**: calendar_days horizon mode measured — AUC Δ+0.0025 (within ±0.005 noise), realized −25%, DD worse vs bars-based deployed. Live/backtest parity confirmed NOT broken (live `marketHoursExecutor` trades the same weekend-open sessions via broker `TradingStatus`). Deployed model stays on bars-based horizon. Full table in `docs/metrics.md` ("Same root cause reaches the PRICE model — MEASURED 2026-10-02"); `-horizon-mode calendar_days` (`internal/model/dataset.go:forwardExitIndex`) remains as an unused option.

## Strategy research: absolute label + target-position sizing (2026-09-16, H1+H2)

- **Label vs execution mismatch (H1)**: training labels are excess-to-IMOEX while execution takes absolute long/short positions. `BuildSamples`/`cmd/exportdataset`/`cmd/trainmodel` support `-label-mode absolute`; on a 6-quarter walk-forward (18 equities, 1M deposit, 0.05% commission) the absolute label turned the OOS result from ~0 (excess: +235₽ total, 2/6 quarters positive) into consistently positive P&L. FX tickers (`GLDRUB_TOM`, `SLVRUB_TOM`, `CNYRUB_TOM`) must not be traded: the IMOEX-relative label is meaningless for them and every model that traded them lost 1.2-1.5k₽ on a single gold short.
- **Best found recipe** (walk-forward, 6 quarters, kill-switch on): absolute **10-day** label, deadband 0.5%, thresholds 0.60/0.40, flat **15000₽ notional per position** via `-target-notional` + target-position execution. Result: realized +110742₽ over 18 months (5/6 quarters positive, worst quarter -6238₽), max DD 2.91%, kill switch never tripped (~7%/yr at ~27% max exposure).
- **Rejected after walk-forward**: 1d/3d/5d horizons (weaker than 10d); thresholds 0.65/0.35 (worse than 0.60/0.40); confidence-scaled sizing `min(1, |p-0.5|/0.2)` (churns 300+ trades, loses vs flat notional); notional 20000₽ and the 42-ticker universe (DD 3.8-3.9% breaches the 3% kill-switch limit).
- **Risk gate limits bind sizing**: 0.5% daily loss / 3% drawdown of deposit cap P&L at larger notionals — P&L scales sub-linearly; pick size so max DD stays under 3%.
- **Live wiring done (2026-09-16)**: `risk.target_notional` config field (+ env override) drives `EnsembleSignalSource.TargetNotional` in `cmd/trader`; real Tinkoff exchange lot size is now resolved and cached per ticker (`brokertinkoff.Sandbox.ResolveLotSize`, backed by `ShareBy`) and injected into `FeatureContext.LotSize` via a `lotSizeSignalSource` decorator before the model sees the signal. This mattered: the walk-forward validation above never modeled real lot size (backtest always saw `LotSize=0`, i.e. implicitly lot=1/share-based sizing); of the 18 tradable equities, GAZP/GMKN/MTSS/RUAL actually trade in lots of 10 (checked live via Tinkoff sandbox `ShareBy`, rest are lot=1) — without this fix, live orders on those 4 tickers would have been sized ~10x too large. The quantization this introduces vs. the walk-forward's continuous sizing is minor (~7-13% step at 15000₽ notional) and not expected to change the sign/order of magnitude of the result, but it hasn't been re-validated in a lot-aware backtest.
- **Feature-subset rule (2026-09-17)**: the 8 event features are structurally zero without a news/event backfill, and with `colsample_bytree`/`feature_fraction` 0.8 they *dilute* the sampled columns and degrade the walk-forward result (18 trained columns + 0.8 = +110741₽; the same recipe over 26 columns = +80716₽; colsample 1.0 = +87823₽). The deployed `ensemble_model.json` therefore trains on the 18 price/flow features and exports `feature_order` over the full 28-name order (`ENSEMBLE_FEATURE_ORDER` in `scripts/export_ensemble.py`, logistic arrays expanded by name), so live inference still passes the feature-order check. Revisit once event/topic features carry real data.
- **Time-exit rejected for the daily strategy (2026-09-17)**: `-max-hold-bars 10` (exit at the label horizon) scored +52498₽ vs +87823₽ for hold-until-flip on the same 6 windows (worse in 4/6, q4 -17388₽ vs -7671₽). The engine supports both (`MaxHoldBars` and flat signals), but daily trading should hold until the signal flips.
- **Intraday 10-min has no edge (2026-09-17)**: 10-min ISS pipeline (62k train bars, 6-bar horizon) gave val AUC 0.5173 and ~-12.8k₽ val P&L with the kill switch tripping — the same ~0.52 AUC ceiling as daily. More data volume alone did not create edge, so "data volume is the bottleneck" is not confirmed by this test. **Dropped by user decision (2026-09-17): no intraday scalping.**
- **Retrained artifact (2026-09-17)**: `ensemble_model.json` is now the absolute-10d recipe (18 features, colsample 0.8, 28-name order with zero-weight placeholders); preflight window +79453₽, DD 0.84%, kill switch off. `config.sandbox.yaml` is updated to match: `ensemble_path`, `risk.target_notional: "15000"`, `risk.max_lots: 1000` all active (commit 722353e); lot size comes from `brokertinkoff.Sandbox.ResolveLotSize` injected as `FeatureContext.LotSize`.
- **Invariant rule — judge strategies by realized, not MTM (2026-09-17)**: a backtest's headline Net P&L must always be split into realized (closed trades, gross − commission) and unrealized (open positions at the cutoff date); MTM is shown separately but never drives a go/no-go. This is the second time the two were conflated — for cross-sectional csvprob: `xsec_full.md` Net +8061 is MTM with realized only +621.80₽ over 2 years (gross +820.22 − commission 198.42), and `xsec_0.8_3000.md` headline +2020 is entirely open-position MTM while realized is −5068₽ (gross −4977.37). A spread proxy (half-spread per side, e.g. `(High−Low)/Close/4`) must be included before trusting any backtest on mid/low-liquidity names — commission×4 is not a substitute for 0.5-2% spreads.
- **Cross-sectional ranking closed (2026-09-17, user decision)**: xsec/csvprob is NOT an upgrade over the deployed abs-10d recipe — realized ≈ 0 (minus on liquid large caps), top "wins" are a handful of multi-month directional bets in mid names (CHMF SELL +1906₽ held 9 months, BANEP/ENPG/ALRS) that backtest's no-spread model can't price, and DD 4.26% breaches the 3% kill-switch limit. abs-10d stays the live signal (realized +110741₽/18mo on 18 liquid names, DD ≤2.91%). Do not reopen this direction without a realized-vs-MTM split and a spread proxy in the validation.
- **Backtest spread+slippage added (2026-09-17)**: `backtest.Config.SpreadPct`/`SlippagePct` (CLI: `-spread-pct`/`-slippage-pct`, default 0 = old behavior) widen every fill against the trader — BUY up, SELL down — applied in `Engine.fillPrice`, covering opens/adds/reduces/flips and `-max-hold-bars` forced exits. Not wired into `cmd/trainmodel`'s holdout validation yet. On the deployed abs-10d ensemble (18 liquid names, 15000₽/position, 18mo): no-cost +43891₽ → realistic (0.05%+0.05%) +43082₽ (−1.8%) → harsh (0.1%+0.1%) +42270₽ (−3.7%); strategy stays profitable but headline P&L without costs is optimistic by a few percent.
- **Live order-execution safeguards added (2026-09-17)**: Tinkoff sandbox was placing bare `MARKET` orders (no price bound at all — the exact "stop-market sweeps the book" risk). Switched `config.sandbox.yaml` to `order_type: limit` and added a marketable-limit slippage cap (`risk.max_slippage_pct: "0.003"`, `internal/executor/live.go:boundedLimitPrice` — BUY caps at price×1.003, SELL floors at price×0.997; order fills within the band or not at all). Also added `risk.no_trade_after_open_minutes: 15` (skips new orders in the first 15 min after the 10:00 MSK open, widest-spread window) and `risk.blackout_windows` (config-driven `"RFC3339-start/RFC3339-end"` list for e.g. CBR key-rate announcements — filled with the remaining 2026 CBR key-rate dates 2026-10-23 and 2026-12-18, verified against cbr.ru, commit `7b97843`). Both live in a new `tradingWindowExecutor` wrapping `marketHoursExecutor` in `cmd/trader/main.go`.
- **News-aware retrain deployed (2026-09-17)**: live news ingestion window widened 2d→10d (`internal/orchestrator/ingest.go: newsWindow`, `telegramLiveMaxPages` 3→15 to actually reach back that far) and confirmed already ticker-filtered before reaching the model (`filterMatches` in `ingest.go`). The previously-deployed `ensemble_model.json` had **zero** learned weight on `news_sentiment`/`news_count` (coef 0.0 in the logistic head, 0 of 13180 tree splits) simply because training data had no real news history — not a deliberate exclusion (only the 8 event_* features were deliberately dropped, see the 2026-09-17 feature-subset rule above). Backfilled 6 months of real Telegram news (9171 articles, `cmd/newsfetch -retro-from`), scored with `news_classifier.json`, and retrained the same 18-feature abs-10d recipe on it (`cmd/exportdataset -news-history` + `scripts/export_ensemble.py`). Holdout comparison on an identical window (2026-06-19..09-17, 1M deposit, 15000₽/position, spread+slippage 0.05%+0.05%, **realized** P&L not headline MTM): with real news +56379₽/253 trades/DD 1.60% vs an identical-window no-news control +40102₽/205 trades/DD 1.09% — a genuine ~40% realized-P&L improvement, not MTM noise (checked both ways). Re-adding the 8 event features on top of real news (541/15187 rows non-zero, still sparse) still underperforms the 18-feature set (+31161₽ vs +33395₽ MTM on the smaller pre-correction run) — the 2026-09-17 feature-subset finding holds even with partial real event data. Deployed: `ensemble_model.json` replaced, 90-day no-news preflight check (matches the live startup gate, which does not inject `-news-history`) passed at +25699₽. Caveat: holdout is 3 months (205-253 trades) with the news backfill mostly overlapping the training side of the split — not a multi-quarter walk-forward; revisit once more months of live news accumulate.
- **RF macro factor-weighting proposal — logged, not implemented (2026-09-17, split-debate consensus)**: user proposed hand-normalized weights for 7 macro factors (negotiations/sanctions 35%, geo-oil/Iran 20%, Fed decision 12%, CBR rate 12%, OPEC+ 10%, AI-bubble 8%, RF dividends 3%) as classifier priors. Debate consensus (Skeptic vs Proponent, 2 rounds, no dissent): do not hardcode hand-set weights anywhere — this model only takes learned coefficients; no ingestion infra exists for oil/Fed/CBR-rate price series (verified zero matches in the Go codebase); headline-triggered detectors for OPEC+/Fed/CBR/Iran would repeat the already-documented "sparse event features dilute `colsample_bytree`" failure at 4x scale, and OPEC+/Fed/CBR additionally need outcome-direction classification (hawkish/dovish, cut/hold), a harder problem than the presence-only detection `event_sanctions` does. Gated backlog: revisit only after (a) `negotiations-sanctions-signal-feature`'s own AUC/backtest evidence gate reports whether the simpler negotiations/sanctions signal helps at all, and (b) the attempt-registry/DSR-PBO infrastructure from the strategy-validation plan exists, so this doesn't get added as an ad hoc untested feature.
