# Новости, события и обнаружение инцидентов

Прочитать перед правкой `internal/ingestion/news`, `cmd/newsfetch`, `cmd/trainnewsmodel`, `internal/features/events.go`, `internal/features/incident.go` или новостного гейта в `cmd/trader`.

## GDELT — пробовали и отказались, не возвращать

- Полностью удалён (`cmd/gdeltnews`, `internal/ingestion/gdelt`, связанные флаги в `trainmodel`/`calibrate`) после повторяющейся нестабильности: геоблокировка без SOCKS-прокси, жёсткий лимит 1 запрос/5 с и всё равно спорадические 429, требующие паузы 55-90 с даже через прокси. Исторические новости теперь идут через `internal/ingestion/news` (RSS). Не добавлять зависимость от GDELT снова, не решив сначала проблему лимита частоты.
- `Kasymkhan/RussianFinancialNews` (HuggingFace; зеркало на Kaggle как `kkhubiev/russian-financial-news`) — кандидат в исторический набор новостей, но он покрывает лишь 2009-06-19..2024-12-16 — не пересекается с текущим обучающим окном (2024-09..по настоящее время) и не заменяет живую историю новостей.

## Платный новостной API/канал — исследовано и отклонено (2026-09-28)

- Поводом был вопрос «стоит ли платить за новостную ленту, чтобы исправить нестабильность/покрытие RSS». Перепроверено двумя независимыми агентами (эта сессия + сессия `opencode` в соседней панели agterm), исследовавшими параллельно, плюс живые пробы по каждому кандидату. Вердикт: **платить не за что.**
- **Первопричиной нестабильности была ошибка в коде, а не ограничение частоты/покрытия** — см. пункт про `User-Agent` в `docs/knowledge/validation-and-ops.md`. Исправление бесплатно.
- **Торговый цикл в любом случае ограничивает, насколько задержка новостей вообще важна.** `cmd/trader` выполняет весь цикл решений с `poll_interval: 5m` (`config.yaml`), а новостной гейт-вето (`newsGateSignalSource.Generate`) вычисляется только раз за цикл — доставка новостей быстрее минуты ничего не даёт, пока сама эта частота не сокращена. Больший потолок задержки — бесплатные котировки MOEX ISS, отстающие на **~15 мин** для акций (`docs/plans/20260927-moex-pulse.md`) — на два порядка больше любой разницы между RSS и платным API. Не возвращаться к «платить за меньшую задержку новостей», не сократив сначала `poll_interval` и не уйдя с отложенных котировок.
- **Лицензированные российские ленты (Интерфакс СКАН/IFX, AK&M, ТАСС Б2Б, `commerce.1prime.ru`) не публикуют цен для самостоятельного заказа и подключают только через подписанный договор с юридическим лицом + расчётный счёт** — физическому лицу недоступны независимо от бюджета. В форме заказа AK&M нет поля для физического лица.
- **У T-Invest API нет эндпоинта новостей** — подтверждено на живом шлюзе gRPC (`NewsService/GetNews` → 404 на каждом испробованном хосте/токене) и поиском по полному справочнику REST Finam Trade API (39 эндпоинтов, ноль совпадений `news`/`feed`). Ни одна из двух уже имеющихся в репозитории интеграций с брокерами не может бесплатно дать новости.
- **Зарубежные новостные API ненадёжно покрывают российские бумаги MOEX.** Marketaux индексирует 14 из наших 17 тикеров как сущности (`TICKER.ME`), но его живой запрос `countries=ru` вернул `found: 0` статей; покрытие РФ у Event Registry не проверено (эндпоинты отвечают 401 без оплаты). NewsAgent Data ($29+/мес, единственный поставщик с опубликованной ценой для самостоятельного заказа) оказался агрегатором тех же публичных источников RSS/Telegram, которые мы и так опрашиваем, без поля фильтра по тикеру, а его бесплатный уровень не вернул ни одной проверяемой статьи РФ.
- **Вместо этого добавлены бесплатные источники:** `iss.moex.com/iss/sitenews` (операционные уведомления биржи, без авторизации, `SourceTypeMOEXSiteNews` в `internal/ingestion/news`), `cbr.ru/rss/RssPress` + `/RssNews` (Банк России — единственный источник, покрывающий регулятора, чьи решения по ставке напрямую двигают SBER/VTBR/T/POSI) и ленты по тикерам `news.google.com/rss/search` (`GoogleNewsSources`/`AllSources` в `internal/ingestion/news/sources.go`, запрос = основной алиас из `DefaultAliases()` + «акции»/«цена»/«курс») — все подключены в `news.AllSources(cfg.Tickers)`, которым пользуются и `cmd/trader`, и `cmd/newsfetch`. Google уже дедуплицирует одну и ту же перепечатку из 4-5 захардкоженных RSS-лент — это дополнительное покрытие, а не механизм дедупликации существующих источников. `disclosure.1prime.ru` (сервер существенных фактов эмитентов, аккредитованный ЦБ, бесплатный для чтения, ключ — ИНН/ОГРН, а не тикер) проверен вживую, но **пока не реализован** — нет RSS/API, нужен специальный скрейпер и карта ИНН→тикер (строится бесплатно из `iss.moex.com/iss/securities.json`); взять как отдельную задачу, а не быстрое исправление.
- **Решение по условиям использования ПРИНЯТО пользователем 2026-09-29 (заменяет «отмечено, пока не действовали»):** условия лицензирования контента Telegram запрещают использовать данные платформы для обучения/дообучения ML-моделей, а уведомление об авторских правах ленты Google News RSS ограничивает использование «отображением результатов в персональном ридере для личного некоммерческого использования». Оба пункта были явно предъявлены (Telegram 2 канала MarketTwits/Банкста, плюс 17 лент Google News по тикерам, добавленных 2026-09-29) как гейт с альтернативой только RSS+MOEX+ЦБ; **пользователь выбрал включить Telegram и Google News в обучающий набор, сознательно принимая риск.** Архив записывает `source` и `trust_weight` по каждой записи (структура `record` в `cmd/newsfetch`), так что пересборка с фильтром по источникам остаётся возможной позже, если решение изменят. Поэтому все числа ниже о классификаторе тональности измерены на наборе, содержащем источники с ограниченными условиями использования, — не выдавать эти числа так, будто источники чистые, и не продолжать бэкфилл молча без повторного подтверждения этого решения.
- То же решение относится и к пути бэкфилла `-news-history` ценовой модели, а не только к `cmd/trainnewsmodel`.
- **Классификатор тональности МЁРТВ, и переобучение его не исправит (2026-09-29, вторая, более крупная попытка).** Развёрнутый `news_classifier.json` ставит 92% заголовков внутри ±0.1 (диапазон [−0.247, +0.266] на 800 уникальных заголовках архива, лишь 7.8% превышают |0.1|) — `news_sentiment` вносит в живой вектор признаков примерно ничего, а его val acc 0.529 ниже мажоритарной базы 0.552. Пересборка архива с нуля (9596 статей: RSS/Google/ЦБ/MOEX `-since-days 30` + Telegram `-retro-from 2026-04-01`) и переобучение дали **четыре** варианта, все ниже базовой точности (val AUC 0.493–0.540, точность 0.469–0.538 против базы 0.511–0.580) с разрывом train→val AUC 0.31–0.46. Свежеобученные модели *живые* (~64% оценок превышают |0.1|), тогда как развёрнутая мёртвая, — так что развёртывание любого варианта заменило бы безвредный почти нулевой признак активно неверным. Артефакт от 2026-09-16 оставлен. Полная таблица и поведенческий прогон оценки — в `docs/metrics.md` («News classifier rebuild from a fresh 9596-article backfill»).
- **Архив невозможно пересобрать до глубины 2026-09-16 (потеря выборки в 17 раз).** 9596 статей дают лишь 2855 обучающих выборок: `BuildNewsLabels` отбрасывает тикеры, чей `source.History` не удался (`internal/model/newsclassifier.go:246`), и обрезает хвост, где `exitIdx >= len(candles)`. У классификатора от 2026-09-16 было 48294 обучающих выборки против 2855 сегодня, потому что ретро Telegram достигает только 2 каналов, а RSS/Google не предоставляют API истории. Не повторять разовое переобучение с бэкфиллом — это задокументированное узкое место нехватки данных, а не проблема настройки. Повторять только после того, как месяцы живых дописываний `cmd/newsfetch` накопят корпус, сбалансированный по меткам направления.
- `cmd/trainnewsmodel` **не** фильтрует по настроенным тикерам — он обучается на каждом тикере архива. Свежий бэкфилл доминируется не-конфигурационными именами (один VKCO — 41.5% из 9596 записей, плюс 8.5% FX-тикеров, которыми модель вообще не должна торговать), поэтому фильтрация до 17 тикеров конфига *навредила* (val AUC 0.493, 759 обучающих выборок). Предфильтровать архив до `config.tickers` перед обучением и держать FX (`GLDRUB_TOM`/`SLVRUB_TOM`/`CNYRUB_TOM`) вне его полностью.
- Google News RSS требует `?hl=ru&gl=RU&ceid=RU:RU` и возвращает перенаправление (`302`) перед настоящей лентой — `http.Client` в Go следует ему автоматически, особой обработки не требуется, но не удалять параметры запроса при построении URL, иначе у цели перенаправления теряется нормализация регистра `ceid`.

## Детектор инцидентов (2026-10-09)

- `features.DetectIncident`/`CountIncidentSources` (`internal/features/incident.go`) помечают физические инциденты (удар дрона/ракеты по объекту, пожар/взрыв на объекте, остановка работы объекта) в заголовках последних 48 часов, считая различные источники в `FeatureContext.IncidentCount`. Его НЕТ в `ToVector`/`defaultFeatureOrder` намеренно (разреженные событийные признаки разбавляют `colsample_bytree`, см. правило подмножества признаков).
- `newsGateSignalSource` блокирует BUY (HOLD, причина `incident`) при `IncidentCount >= news.incident_min_sources` (по умолчанию 2) и шлёт алерт в Telegram с cooldown 6 ч на тикер; SELL никогда не блокируется. Ключи: `news.incident_veto_enabled`, `news.incident_min_sources`. Работающему `./trader` нужна пересборка, чтобы это подхватить.
- `\w` в regexp Go — только ASCII: для кириллических суффиксов нужен `[а-яё]*`. Первый черновик этого детектора с `\w*` пропустил 12 из 13 заголовков про Сасово для YDEX. Известный источник ложных срабатываний: тикеры с широкими алиасами (VKCO) получают общие новости, отсюда минимум 2 источника.
- Независимость источников (2026-10-09): `CountIncidentSources` сводит семейства издателей (`Google News: *`, `Ведомости*`, `ЦБ РФ: *`) в один источник через `incidentSourceFamily`, так что три раздела «Ведомостей» больше сами по себе не выполняют `incident_min_sources: 2`. Каналы Telegram (MarketTwits, Банкста) остаются различными, но в основном перепечатывают одни и те же ленты; дедупликация по ленте и алерт о всплеске заголовков НЕ строились, потому что событий `incident` всего 12 (для порога нужно >= 30 живых срабатываний). Работающему `./trader` нужна пересборка.
- Шорт по инциденту (2026-10-10, поверх вето): при `news.incident_short_enabled: true` активный инцидент (>= `incident_min_sources` источников за 48 ч) превращает BUY или HOLD в SELL того же размера, что и у модели (тот же `TargetLotsForNotional` из `risk.target_notional`/`max_lots`/`vol_scale`, по `feature.LotSize`); существующий SELL ценовой модели остаётся нетронутым. Риск-гейт его ограничивает (`max_net_short` был 90000 в config.sandbox.yaml), а исполнитель пропускает, когда позиция достигла цели, так что повторные 5-минутные сигналы SELL идемпотентны. Шорт открывается только по новостям — гейт preflight не видит новостей (реплей только по модели), поэтому шорты по инцидентам не бэктестируются; позиция выходит естественным образом после истечения 48-часового окна инцидента, когда модель больше не даёт SELL. Считается счётчиком Prometheus `incident_shorts_total{ticker}`. Ключ конфига: `news.incident_short_enabled`. Работающему `./trader` нужны пересборка и перезапуск, чтобы это подхватить.

- Выход из новостной позиции (2026-10-10): при `news.exit_enabled: true` шорт, открытый гейтом инцидентов, отслеживается (`cmd/trader/newsexit.go`, состояние в `news.exit_state_path`, по умолчанию `artifacts/news_trades.json`) и закрывается сигналом `Flat` (BUY/SELL с `TargetLots=0`, `Flat=true`; `TargetPositionExecutor` и оркестратор трактуют его как желаемую позицию 0, так что он никогда не может перевернуть позицию). Триггеры выхода: `stop_loss` (неблагоприятное движение >= `exit_stop_loss_pct`), `take_profit` (пиковая прибыль >= `exit_take_profit_pct` и откат на `exit_trail_pct` от пика, то есть новостной импульс угас и рынок корректируется), `time_exit` (`exit_max_hold`). Сигнал выхода повторяется каждый опрос, пока позиция не станет плоской; затем `exit_cooldown` на тикер (по умолчанию 48 ч = окно инцидента) блокирует новый шорт по инциденту, иначе тот же инцидент открыл бы шорт заново сразу после take-profit. Закрываются только позиции, открытые менеджером: шорт, существовавший до инцидента (книга модели), не отслеживается и остаётся нетронутым. Значения по умолчанию (1.5% / 0.7% / 2.5% / 24 ч) НЕ настроены: они масштабированы от наблюдаемого CAR[0,+1] по инцидентам около -2.3% при N=12 и требуют пересчёта, когда появится >= 30 живых срабатываний инцидентов. Не бэктестировалось (реплей preflight не видит новостей). Состояние трекера хранится в `audit_events` (стадия `news_trade_state`, id `news-trade-state`), поэтому оно переезжает вместе с синхронизируемым `trader-sandbox.db` при failover; `exit_state_path` — лишь запасной вариант для запусков без хранилища. Дальнейшие шаги: `docs/plans/20261010-news-exit-tuning-and-buy-side.md`.

## Причинное событийное исследование (2026-10-09)

- **Причинное событийное исследование новостных тем проведено (2026-10-09), DiD/TWFE/AIPW, эффекта не найдено.** `cmd/eventstudy` на 17 тикерах x 140 дней: `sanctions` (71 событие) и `negotiations` (58) не показывают рыночно-скорректированного эффекта на CAR[0,+1] или CAR[+1,+5] (ДИ stacked DiD и AIPW включают 0, MDE ~1%); `incident` направленно отрицателен (-2.3%), но N=12 недостаточно для мощности (Holm p 0.078). IV намеренно не запускался (нет валидного инструмента). Протокол `docs/plans/completed/20261009-event-causal-study.md`, числа в `docs/metrics.md`. Не открывать заново без новостного архива в несколько раз больше.

- Сопоставление тикеров и отраслевое отображение (2026-10-11): `Matcher` раньше делал простое подстрочное совпадение, поэтому алиас VKCO `вк` совпадал внутри слова «по**вк**ам», и вся история про санкции на дизтопливо от 2026-10-09 (звонок Трампа и Путина, ~25 заголовков) была отнесена к VKCO/MOEX, и ничто из неё не дошло до ROSN/LKOH/TATN. Алиасам длиной <= 4 рун теперь нужны границы целого слова (`containsAlias`); более длинные должны начинаться с границы слова, чтобы словоформы всё ещё совпадали. `news.industry_matching: true` (по умолчанию выключено) добавляет `IndustryRule` (`DefaultIndustryRules`): заголовок с отраслевым ключевым словом (например «дизел», «нефтепродукт») также прикрепляется к тикерам сектора как `MatchedArticle.Indirect` с половинным доверием источника. `CountIncidentSources` намеренно пропускает косвенные совпадения: общеотраслевая история вроде «санкции сняты» для детектора инцидентов не имеет направления и открыла бы шорт по инциденту именно по тем тикерам, которым она помогает. Включение сдвигает значения `news_*`/`event_*` признаков для нефтяных тикеров относительно того, на чём обучалась модель, поэтому прогнать гейт preflight перед включением в лайве. По-прежнему нет пути BUY из новостей (см. `docs/plans/20261010-news-exit-tuning-and-buy-side.md` §3).

Шорты по инцидентам срабатывают один раз за эпизод (2026-10-14): 48-часовое окно заставляло `incident-short` срабатывать заново в каждом 5-минутном цикле (1000+ строк лога для YDEX). `SummarizeIncidents` даёт начало последнего эпизода (кластеризация разрывов по 12 ч) и время последней статьи; `newsExitManager.claimIncident` сохраняет отметку по тикеру и разрешает шорт только если эпизод начался после неё и ему не больше 6 ч, так что последующее освещение и перезапуск не открывают шорт повторно. BUY-вето действует на всё окно.
Фильтр ретроспективы (2026-10-14): `news.lookback_move_pct` (по умолчанию 3, 0 отключает) пропускает вход по новости, если 5-дневное движение уже пошло в ту же сторону (шорт после падения не менее чем на столько процентов, покупка после роста). Эпизод всё равно расходуется, так что пропущенный первый отчёт не повторяется в следующих циклах. Сегодня им пользуется только шорт по инциденту; `movePriced` — крючок для будущего новостного BUY.
Правило опровержения (2026-10-14): статья в окне, которая упоминает удар, но сообщает о нормальной работе, отсутствии ущерба или о сбитых дронах/недолёте до цели (`DetectIncidentDenial`, случай дата-центра СБЕРа в Балакове), выставляет `IncidentDenied`. Опровергнутый инцидент не открывает шорт, а отслеживаемый новостной шорт закрывается (`forceExit`, причина denied), когда опровержение появляется позже. BUY-вето по-прежнему действует.
LLM-вето для шортов по инцидентам (2026-10-14, одобренное владельцем исключение из решения от 2026-09-15 «никакого LLM на торговом пути»): `internal/incidentcheck` один раз за эпизод инцидента спрашивает qwen3.8 на ai-box (`news.incident_check_url`), показывают ли заголовки реальный ущерб. Шорт открывается только при `damage`; `no_damage`/`unclear` расходуют эпизод без сделки; ошибка или таймаут проверяющего ничего не открывают, восстанавливают отметку эпизода и откладывают на 10 минут, так что первый отчёт повторяется, пока он свеж (6 ч). LLM может только отменить шорт, но никогда не создать его и не трогает BUY/SELL от модели. Пустой `incident_check_url` отключает его. Живая проба: заголовки про Балаково (СБЕР) -> no_damage, пожар/остановка YDEX -> damage.

`news.lookback_vol_mult` (2026-10-15, по умолчанию 0 = выкл.): предел ретроспективы становится max(`lookback_move_pct`, mult x дневная реализованная волатильность x sqrt(5)), так что движение 4% заложено в цене для спокойного банка, но обычный шум для волатильного тикера. Множитель НЕ откалиброван: событийное исследование по нему не проводилось, поэтому он остаётся выключенным в конфиге, пока такое не будет предрегистрировано. Источник идеи: кластеризация волатильности в духе GARCH (Simonov & Akhunyanova 2019 прочитана и отклонена как источник сигнала: её p-адические прогнозы статистически незначимы на 7 инструментах и не проверены вне выборки).

## LLM в контуре риска: правила и пробелы (2026-10-18)

Правила, которые уже соблюдаются в коде (не ослаблять без владельца):
- LLM никогда не создаёт позицию и не трогает BUY/SELL модели: `internal/incidentcheck` может только подтвердить (`damage`) или отменить шорт по инциденту; `no_damage`, `unclear`, пустой список заголовков, ошибка или таймаут — всё это означает отсутствие сделки (`cmd/trader/incidentcheck.go`). Детерминированные гейты (риск-гейт, kill switch, `max_net_short`, новостное вето) работают после него, и он не может их переопределить.
- Отказ закрытый: недоступный проверяющий ничего не открывает и откладывает на 10 минут; пустой `news.incident_check_url` полностью отключает путь и возвращает детерминированный детектор.
- Область исключения: одобрено владельцем 2026-10-14 только для шортов по инцидентам; любое другое использование LLM на торговом пути требует нового одобрения (решение от 2026-09-15).

Пробелы, найденные 2026-10-18 (не исправлены, они затрагивают торговый путь и требуют решения):
- Аудит: вердикт записывается только в текстовый лог как `ticker, verdict, reason`. Отправленные заголовки, имя и версия модели, сырой ответ и хэш промпта не сохраняются, поэтому решение нельзя восстановить постфактум. Предложение: одна JSONL-запись на проверку (время UTC, тикер, модель, хэш промпта, заголовки, сырое содержимое, разобранный вердикт, исход) рядом с `news.exit_state_path`, с регрессионным тестом, что запись есть для каждого исхода, включая ошибку.
- Воспроизводимость: модель адресуется по тегу (`qwen3.8:latest`), так что обновление молча меняет поведение. Предложение: зафиксировать digest в конфиге и записывать его в каждую запись.
- Нет монитора качества: доля вердиктов `damage` и их последующий ценовой исход не отслеживаются, поэтому дрейф проверяющего не виден. H5 и H12 в `docs/plans/20261015-hypotheses-from-llm-review.md` описывают проверки, которые нужно запускать по журналу вердиктов, когда он появится.

Статус локализации (что специфично для русского языка, а что нет): детекторы инцидентов и тем с учётом кириллицы (`[а-яё]*`, не `\w`), российские источники (РБК, Ведомости, Интерфакс, ЦБ, уведомления MOEX), календарь биржи и ряд ключевой ставки ЦБ. Измеренный предел: классификатор заголовков по мешку слов, обученный на 18375 русских выборках (2021-2024), не показывает направленного сигнала на 2026 (`docs/metrics.md`, «Data depth, step 2»); направление от LLM zero-shot по русским заголовкам (H2) не запускалось. Поэтому локализация сделана для обнаружения и фильтрации, но не для тональности как альфы.

## Слияние архива и расширение универсума тикеров (2026-10-18)

Почему только 17-18 тикеров: матчер `news.DefaultAliases()` знал только тикеры конфига, поэтому каждый импортёр давал пары только для них (сам датасет Kasymkhan размечает около 200 из 260 акций TQBR). `news.Universe` (`internal/ingestion/news/universe.go`) теперь сопоставляет каждый тикер из `data/ticker_names.json` (короткие, полные и латинские имена ISS, `cmd/listtqbr -names-out`), курируемые `DefaultAliases` и алиасы, выученные по собственным тегам датасета вида `<name> <TICKER>`. Он обрабатывает русские падежные окончания (основа плюс фиксированный набор суффиксов, так что `Магнита` совпадает, а `магнитное` нет), многословные имена, `#TICKER` / `$TICKER` и держит пару привилегированная/обыкновенная (`SBER`/`SBERP`) как одну компанию. Алиасы, отображаемые на несколько разных компаний, отбрасываются.

Слито в `data/news_history.jsonl` (в gitignore; снимок предыдущего файла из 14799 пар хранится только в каталоге scratch сессии) командой `cmd/newsimport -names data/ticker_names.json -alias-blocklist data/news_alias_blocklist.json -parquet <train> -parquet <test> -jsonl data/news_history.jsonl -jsonl newssent/data/news_all.jsonl -jsonl newssent/data/news_backfill.jsonl -jsonl newssent/data/live/{news_merged,wires,news_live}.jsonl -jsonl <iss_sitenews converted>`. Старые записи не тронуты (новый файл начинается со старых 14799 строк), дубликаты отбрасываются по тикеру плюс id статьи и по тикеру плюс нормализованному заголовку.

Результат: 101082 пары тикер-статья, 70670 уникальных id статей, все 260 акций TQBR присутствуют (146 минимум с 50 парами, 84 минимум с 200, 25 минимум с 1000; самые слабые — однозначные числа). Годы 2021-2024: 6072 / 12175 / 24893 / 23874 пар; 2025: 8785; 2026: 20528. Дыра декабрь 2024 - март 2026 больше не пуста (около 500-900 пар в месяц: бэкфилл Telegram и уведомления биржи), хотя всё ещё тонкая по сравнению с 2023-2024. Источники: bcs 19.4%, smart_lab 14.9%, finam 12.6%, уведомления сайта MOEX 12.1%, MarketTwits 12.0%, bcs_tech 8.9%, Банкста 6.6%, rdv 3.6%, t_invest 2.9%; Telegram 18.7%, Google News 4.6% (раньше: 62.5% и 28.6%). `VKCO` упал с 28.5% до 4.5% пар за счёт разбавления, собственные записи не изменились.

Проверка качества (против собственных тегов тикеров датасета как истины, `-audit`): сопоставление только по заголовку достигает точности 90.5% на 3995 попаданиях (3617 верных) и восстанавливает 3655 из 15514 размеченных тикеров (23%; в большинстве размеченных статей компания названа только в тексте). Теги используют выведенные из обращения тикеры, отображаемые через `renamedTickers` (`YNDX->YDEX`, `TCSG->T`, `HHRU->HEAD`). Набор тестов матчера поймал настоящее ложное срабатывание (общее первое слово «мобильные», привязывавшее MTS), а аудит нашёл другие, теперь заблокированные в `data/news_alias_blocklist.json`: общие или конфликтующие слова (самолёт, пик, позитив, ренессанс, авиакомпания, элемент, кристалл, яковлев, дом, биржа), унаследованные неверные алиасы (у `SMLT` было имя Segezha) и слова про FX-металлы. Точность алиасов на размеченных заголовках завышает точность на общих новостях, потому что размеченные статьи специфичны для финансов.

Известные пределы, чтобы их не открывать заново:
- Дайджесты BCS («Ход торгов», «Старт дня») размечаются BCS каждым упомянутым тикером; они становятся парами рыночных комментариев для этих тикеров. Использовать `-max-tickers-per-article` в `trainnewsmodel` или фильтровать по источнику.
- 12.1% пар — уведомления сайта MOEX (параметры риска, ценовые коридоры, уведомления о листинге): официальные и с отметкой времени, но почти пустые как текст тональности; фильтровать по источнику `MOEX сайт-новости` при обучении классификатора.
- Имена, являющиеся обычными словами (Магнит, Полюс, Лента, Эталон, Астра), всё ещё оставляют шум вне финансовых изданий.
- 97% строк Kasymkhan несут дату без времени, поэтому внутридневное использование для них невозможно; вход по открытию следующего торгового дня (`BuildNewsLabels`) исключает заглядывание вперёд в тот же день.
- Лицензирование: карточка Hugging Face у `Kasymkhan/RussianFinancialNews` сообщает Apache 2.0, зеркало Kaggle, используемое `newssent`, записано там как CC BY-SA 4.0; исходные тексты — из Finam, BCS, РБК, T-Invest и Smart-lab. Считать это исследовательскими данными, сохранять указание авторства, не распространять слитый файл. Прежнее решение об условиях использования Telegram и Google News (2026-09-29) не изменилось, нового скрейпинга не добавлялось.
- Результаты, измеренные до этого слияния (шаги 2 и 2b классификатора новостей в `docs/metrics.md`), использовали старый архив из 14799 пар плюс импорт Kasymkhan для 18 тикеров конфига; здесь они не пересчитываются.

### Очистка архива и воспроизводимая пересборка (2026-10-18, одобрено владельцем)

Архив до слияния содержал привязки к тикерам, которых его источники никогда не поддерживали (`newssent` измерил около 43% строк с перенацеленной привязкой; здесь 4211 из 4566 пар `VKCO` были макро-постами Telegram, релизы PMI еврозоны и Японии были привязаны к `OZON` и `POSI`). `cmd/newsclean` переносит такие пары в файл карантина вместо удаления, с указанием причины. Пара остаётся, если заголовок называет её тикер по текущему матчеру, либо это лента Google News ровно для этого тикера, либо она из источника с тегами (bcs, bcs_tech, finam, smart_lab, rdv, t_invest, t_analytic), чей тикер взят из тегов датасета. Всё остальное уходит в `data/news_quarantine.jsonl` (`not_supported_by_text` или `ticker_outside_universe`).

Результат: `data/news_history.jsonl` теперь 94175 пар (65360 уникальных статей), 6916 пар в карантине (4211 `VKCO`, 693 `GLDRUB_TOM`, 564 макро-постов `MOEX`, 194 `CNYRUB_TOM`, остальное разбросано; 6118 из них из Telegram). У всех 260 акций TQBR по-прежнему есть новости (143 минимум с 50 парами, 84 минимум с 200, 24 минимум с 1000). Годы 2021-2026: 6063 / 12130 / 24887 / 23862 / 8698 / 13832. Источники: bcs 20.8%, smart_lab 16.0%, finam 13.5%, уведомления MOEX 12.8%, bcs_tech 9.5%, MarketTwits 9.0%, Банкста 4.5%, Telegram в сумме 13.6%, Google 4.8%. `VKCO` — 0.4% пар. Помещённые в карантин макро-посты (мировой PMI, центробанки, геополитика) — настоящие общерыночные новости и позже могут стать отдельным классом «рынок»; они сохранены, а не выброшены.

Запуск очистки выявил недетерминированный матчер: несколько алиасов с общей основой (например, словоформа двух компаний) перезаписывали друг друга в порядке обхода карты, поэтому два запуска различались примерно на 40 пар. Столкновения основ у разных компаний теперь считаются неоднозначными и отбрасываются, алиасы обрабатываются в отсортированном порядке, а тест строит универсум 60 раз. `scripts/rebuild-news-archive.sh` (нужны `BASE`, `PARQUET_DIR`; необязательные `NEWSSENT`, `ISS_CONVERTED`, `OUT`, `QUARANTINE`) пересобирает весь архив из файла до слияния; два запуска дают идентичные файлы (md5). Файл до слияния (14799 пар) и слитый файл до очистки (101082 пары) хранятся в `~/dev/archive/moex-trader-news/`.

Числа в предыдущем разделе (101082 пары, 70670 статей, 25 тикеров с 1000+, Telegram 18.7%) описывают файл до очистки.

### Больше каналов Telegram, `cmd/tgarchive` (2026-10-18, одобрено владельцем)

Решение владельца 2026-10-18 (ответ «да» на расширение покрытия Telegram после уведомления, что оно увеличивает уже принятый 2026-09-29 риск): тринадцать дополнительных публичных каналов собираются через веб-превью (`https://t.me/s/<channel>`, только чтение, без входа) в сырое хранилище. Условия лицензирования контента Telegram запрещают обучение ML-моделей на данных платформы, и владелец сознательно принимает этот риск, как и прежде; ничего другого к нему не добавлено.

Каналы, проверенные 2026-10-18 на живое веб-превью и недавние посты, с числом постов в день: smartlabnews (9), bcs_express (10), cbonds (10), frank_media (10), cbrstocks (16), prime1 (16), if_market_news (24), finamalert (5), investfuture (5), centralbank_russia (2), interfaxonline (38), kommersant (35), rbc_news (51). Не взяты: `tass_agency` (около 220 постов в день, ТАСС уже приходит через RSS в `newssent`), `headlines_for_traders` (в основном иностранные котировки), `russianmacro` (несколько постов) и каналы без превью (`tinkoff_investments`, `moexofficial`, `oilcapital` перенаправляют в сторону). «Коммерсантъ» доступен отсюда через Telegram, хотя его RSS отвечает таймаутом.

`cmd/tgarchive -channels a,b -since 2025-01-01 -out data/news_raw_tg_x.jsonl -delay 1500ms`: листает назад через `?before=<id>`, делает паузы и повторы с откатом, пишет постранично и возобновляется (сначала новые посты, затем более старый разрыв), так что повторный запуск добавляет только недостающее. Записи имеют форму finanalys с пустым тикером плюс `channel` и `post_id`, так что `cmd/newsimport -jsonl` заново сопоставляет их с универсумом тикеров, а `newsclean` оставляет только те, чей текст называет тикер. Сырые файлы `data/news_raw_tg*.jsonl` в gitignore; `scripts/rebuild-news-archive.sh` их подхватывает. Они намеренно НЕ входят в `news.DefaultSources()`: вето по инцидентам в трейдере считает различные источники (`incident_min_sources`), и добавление туда каналов изменило бы живой гейтинг. Чтобы собирать дальше, периодически перезапускать `tgarchive` (он инкрементален); планировщик не устанавливался.

### Аудит вердиктов LLM и фиксация модели (2026-10-18, одобрено владельцем)

Два из трёх пробелов, перечисленных в разделе «LLM в контуре риска», закрыты. Каждая проверка инцидента теперь дописывает одну JSONL-запись в `news.incident_check_audit_path` (`artifacts/incident_checks.jsonl` в `config.sandbox.yaml`, в gitignore): время UTC, тикер, имя и digest модели, хэш промпта, отправленные заголовки (первые 8), сырой ответ модели, разобранный вердикт и причина, исход (`confirmed`, `rejected`, `error`, `skipped_no_headlines`) и текст ошибки. Сырой ответ сохраняется, даже если разбор не удался. `news.incident_check_model_digest` фиксирует digest образа Ollama (установлен по текущему `qwen3.8:latest` на ai-box); несовпадение проваливает проверку до любого вызова chat, поэтому ни один шорт не открывается, пока фиксация не будет намеренно обновлена после обновления модели. Тесты: проверяющий захватывает происхождение и обеспечивает фиксацию, ошибка разбора сохраняет сырой ответ, журнал аудита дописывает JSON-строки, и трейдер пишет ровно одну запись на исход (`internal/incidentcheck`, `cmd/trader`). Работающему `./trader` нужны пересборка и перезапуск, чтобы ими пользоваться.

Карантин побайтово идентичен между двумя запусками; архив различается на одну пару между запусками лишь потому, что живые входные файлы (`newssent/data/live/news_live.jsonl`, `data/news_raw_tg_live.jsonl`) растут каждые несколько минут. Числа 94175 пар в предыдущем разделе описывают заменённый файл; файл до Telegram хранится в `~/dev/archive/moex-trader-news/`.
