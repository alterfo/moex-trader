## Конвейер признаков

- Порядок вектора признаков задаётся один раз в `internal/model/features.go` (`defaultFeatureOrder`/`ToVector`) и должен зеркалироваться только на стороне Python (`scripts/compare_models.py` `FEATURES`, `scripts/export_ensemble.py`); `cmd/exportdataset` формирует заголовок и строки CSV из `model.ToVector` автоматически. Молчаливое расхождение здесь — ровно тот сбой, что описан в правиле владения 4 из AGENTS.md; негейтированный `TestDeployedModelArtifactsMatchFeatureOrder` теперь сверяет оба отслеживаемых артефакта с `ToVector`.
- Текущий канонический порядок (28 имён на 2026-09-18): 18 ценовых/потоковых признаков — исходные 14 плюс `macd_hist_pct, stoch_k_14, williams_r_14, alligator_spread_pct` — затем 8 флагов `event_*`, затем `negotiations_signal, sanctions_signal`. Развёрнутый `ensemble_model.json` обучается только на 18 ценовых/потоковых столбцах; остальные 10 имён — заглушки с нулевыми коэффициентами, сохраняющие паритет порядка признаков с лайвом.
- `order_book_imbalance` в историческом CSV-экспорте `cmd/exportdataset` структурно всегда 0 — исторических снимков стакана не существует. `news_sentiment` / `news_count` по умолчанию тоже 0, но `cmd/exportdataset -news-history <path>` (добавлен 2026-09-16, зеркалирует `cmd/trainmodel -news-history` и `cmd/calibrate -news-history`) подставит реальные значения из `news_history.jsonl` формата finanalys (см. `cmd/newsfetch`) через `model.LoadFinanalysNewsHistory`/`AggregateDailySentiment`/`AggregateDailyTopicSignals` по тикеру и дате. Без этого флага, а также для дат/тикеров, которых нет в архиве, все три группы по-прежнему равны 0 — поэтому прогон важности признаков на датасете без `-news-history` покажет их мёртвым грузом уже только по этой причине.
- `SBMM` (ETF «First – Savings Fund») НЕ торгуется через T-Invest API (`apiTradeAvailableFlag=false`) — исключён из списка тикеров и заменён на `POSI`. Не возвращать его как цель ордеров.

## XGBoost/LGBM → инференс на Go (решено — не выводить заново)

- Экспортировать через `booster.save_model("model.json")` (полный нативный формат). Никогда `dump_model()` (с потерями, другая схема узлов, нет `base_score`) и не `save_raw()` без `raw_format="json"` (в современном xgboost по умолчанию бинарный UBJSON — подача его JSON-парсеру вызвала зависание парсера при разработке).
- `learner.learner_model_param.base_score` в этом JSON — **строка в скобках**, например `"[4.7E-1]"` — перед разбором во float скобки нужно убрать.
- При `boost_from_average` (значение xgboost по умолчанию) `base_score` хранится в **вероятностном пространстве** (среднее меток), а не в пространстве маржи — перед суммированием с выходами деревьев преобразовать `base_logit = log(bs/(1-bs))`. Это независимо выведено и подтверждено дважды (обеими агентскими сессиями по отдельности) против `predict_proba` — доверять без повторного вывода, если только свежая проверка точности не покажет расхождения.
- Значение листа = `split_conditions[node]` в **листовом** узле (`left_children[node] == -1`). `base_weights[node]` равен ему только в листьях; во внутренних узлах это не порог разбиения и не пригодное значение листа.
- Внутренние сравнения разбиений XGBoost выполняются во float32, у LGBM — во float64. Перед сравнением с порогами разбиения входы деревьев XGB нужно квантовать во float32, иначе на некоторых границах возникают расхождения порядка 0.01. Проверенная сквозная точность относительно Python `predict_proba`: максимальная абсолютная ошибка 6.4e-8 на всём валидационном наборе.
- Итоговая вероятность = `sigmoid(base_logit + Σ значений листьев по всем деревьям)` для `binary:logistic`.
- Подвох рекурсивного построителя JSON деревьев LGBM: добавить заглушку `-1` для индекса потомка **до** рекурсии, затем перезаписать (`lc[i] = walk(...)`). Прямое добавление результата рекурсивного вызова (`lc.append(walk(...))`) выполняет потомков не по порядку и портит индексы плоского массива.
