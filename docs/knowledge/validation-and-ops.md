# Validation tooling and live/sandbox operations

Read before changing `cmd/strategyvalidation`, walk-forward, the shadow reconciler, metrics/alerts, order execution safeguards, the kill switch, or Telegram wiring.

Moved verbatim from AGENTS.md on 2026-10-09; the rules in AGENTS.md itself still take precedence.

## Strategy validation tooling (2026-09-17)

- `docs/metrics.md` is the metrics ledger; its format is enforced by `internal/metricsdoc` (`TestRepositoryMetricsDocumentPassesLint`), and the headline numbers must remain present. Record every analysis number there in the same commit.
- OOS freeze: `artifacts/oos/freeze.json` records the recipe + `code_sha`; `cmd/oosfreeze -action status` reports collection days, reset on a recipe-hash change. Code changes are informational only — treat "any change restarts the count" as a manual check.
- Walk-forward reproducibility: `cmd/backtest -wf-dir` persists per-window models and decision logs (`internal/walkforward`).
- `cmd/strategyvalidation` prints the attempt registry, deflated Sharpe and PBO. PBO is computable from persisted per-window `period_returns.csv` matrices via `-returns-dirs`; the six pre-registered attempts of the 2026-10-04 plan are in the registry and the deployment-gate PBO is 0.1529 (see `docs/metrics.md` "Deployment decision 2026-10 (Task 13)").
- Purged walk-forward is the standard validation: `-embargo-bars 10` in `cmd/walkforward`, `cmd/backtest -wf-dir` and `cmd/trainmodel` (mirrored in `scripts/export_ensemble.py`) drops every training row whose label exit reaches the test window, so the 10-day label no longer overlaps train and validation. The purged run is the deployment-gate control.
- Live-vs-backtest parity: features are built from closed bars and `return_pct` comes from candle closes (`closedBarReturnPct`), not the intraday `LastPrice`; the shadow reconciler (`--shadow-digest`) writes a digest and flags an unclosed trailing bar or a replayed-signal mismatch.
- Live diagnostics: PSI drift warnings (`risk.drift_psi_*`), per-ticker circuit breaker (`internal/risk/tickerbreaker.go`), rebalance hysteresis (`risk.rebalance_min_deviation_pct`) and two-poll signal hysteresis are wired in `cmd/trader`. The per-ticker breaker tracks average entry cost including entry commissions; entry commission is not ignored.

## Live/sandbox operational notes

- Kill switch must only cancel orders for instruments the bot actually trades (its own ticker set) — it must never touch a human's manual orders on the same account. (Regression test: `TestCancelOpenOrdersLeavesForeignOrdersAlone`, added after it was found cancelling unrelated manual orders.)
- The bot only tracks positions from its own fills — it has no visibility into shares a human holds manually on the same account. A SELL signal on a ticker the human also holds manually will be interpreted as opening a short, not "selling the human's shares." This matters before ever wiring live execution onto an account that already has manual positions.
- Telegram: `api.telegram.org` is blocked directly from this environment — route through `telegram.proxy: "socks5://127.0.0.1:3333"`.
- Nightly evening digest (`telegram.daily_summary_enabled` + `daily_summary_time`, default 19:05 MSK): after the close the trader sends a brief Telegram summary — bot day P&L (realized net of commission + MTM change of open positions, `internal/dailysummary`, average-cost accounting mirrors `risk.TickerBreaker`), number of fills, IMOEX daily % and the share of configured tickers that closed green — market context for the user's manual long positions. Runs only inside the lease-holding trader (no duplicate from the standby); non-trading days (weekends/holidays) are skipped via the IMOEX candle date, so it needs only config, not a cron entry. Deployed `config.sandbox.yaml` enables it.
- Finmarket's RSS feed is Windows-1251, not UTF-8 (`internal/ingestion/news/news.go` decodes via `charset.NewReaderLabel`) — don't assume every feed is UTF-8.
- **RSS 429s were a missing `User-Agent`, not real rate limiting (2026-09-28).** `Fetcher.Fetch` sent Go's default `Go-http-client/1.1` UA; live-verified vedomosti.ru returns 429 on 6/6 requests with that UA and 200 on 6/6 with a browser UA. Fixed by setting `newsUserAgent = "Mozilla/5.0 (compatible; moex-trader/1.0)"` (already used by `FetchTelegram`, now shared) on every RSS/JSON request in `internal/ingestion/news/news.go`. Don't add a proxy or paid feed to chase this class of failure again — check the UA first.
- AlgoPack enrichment silently disables itself (one log line) when `MOEX_TRADER_ALGOPACK_TOKEN` is unset, instead of logging a 401 per ticker per cycle.
- Orders are guarded by `TradingStatus` — the bot checks whether the MOEX session is open before submitting, instead of hitting error `30079` (`Instrument is not available for trading`) or burning API rate limit outside trading hours.
- `risk.Gate.ApproveReason` (2026-09-19) returns a `risk.Decision{Approved, Reason}` and the orchestrator now persists the reject reason in the `risk_gate` audit payload (e.g. `{"approved":false,"reason":"fat_finger"}`). `Approve` remains as a delegating wrapper so backtest and callers needing only the bool stay unchanged. Silent reject reasons: `kill_switch_active`, `ticker_breaker_blocked`, `drawdown_limit`, `max_lots_exceeded`, `max_position_exceeded`, `fat_finger`, `daily_loss`, `sector_cap`. When analyzing risk rejections read `reason` from `audit_events` instead of inferring from the absent bool.
- Heavy compute (model training, multi-ticker dataset export: `cmd/exportdataset`, `cmd/trainmodel`, `cmd/calibrate`, `cmd/walkforward`, news-history aggregation) must run on the ai-box (`ssh oleg@192.168.88.193`, repo at `~/moex-trader` on that box), not on the Mac. The ai-box LAN IP is in `watchdog.yaml`'s `peer_url`; the SSH user is `oleg`, not the generic `user` placeholder used elsewhere in this doc. Two parallel `exportdataset` runs (171%/157% CPU) once spun up the Mac to full tilt; kill with `pkill -f exportdataset` and re-run remotely.
- Observability (2026-10-04): `/metrics` exposes `moex_trader_inference_duration_seconds` (renamed from the old `llm_inference_duration_seconds` — the pipeline is a model, not an LLM), `signals_generated_total`, `risk_rejections_total{reason}`, `executor_skips_total{reason}`, `signal_probability`, `candle_age_seconds{ticker}`, `feature_psi{feature}`, `position_notional{ticker}`, `gross_exposure`, `lease_held`, and monitoring-only `var_95`/`var_99`/`es_95`/`es_99` (1-day book VaR/ES from 250-day trailing returns, `internal/risk/var.go`, one line in the daily digest). Telegram alerts are cooldown-gated (`internal/alert/telegram/watch.go`, config `alerts.*`): probability collapse, stale candles, PSI breach. See `docs/metrics.md` "Observability metrics and alerts (Task 6)".
